This section covers `vcluster.yaml`, the file that configures a cluster. It
decides how the control plane runs, where workloads run, which resources sync
with the control plane cluster, and how users and tools connect. You pass the
file when you [deploy a cluster](../deploy/overview.mdx), and you
[deploy config changes](../operate/deploy-changes.mdx) to update a running one.

The file is optional. Without one, a cluster runs on shared nodes from the
control plane cluster's node pool, with its resources syncing to a single
namespace there. To give the cluster dedicated worker nodes instead, configure
[private nodes](./private-nodes/overview.mdx).

## How the file is organized

The file is grouped by top-level key, and each Configure category covers one
area of it. `controlPlane` decides how the API server, backing store, and
CoreDNS run and how the control plane is exposed. `privateNodes` turns on
dedicated worker nodes. `sync` chooses which resources move between the
cluster and the control plane cluster, in both directions. `networking` and
`policies` govern traffic, quotas, and admission. Other keys cover access,
lifecycle, add-ons, logging, and experimental features.

For how the sections fit together, with example files for shared nodes,
private nodes, and vCluster Standalone, see
[What is vcluster.yaml?](./what-is-vcluster-yaml.mdx). To look up one field,
its type, and its default, use the generated
[vcluster.yaml reference](../reference/vcluster-yaml/overview.mdx).

## Settings you choose at creation

Most settings can change on a running cluster. Some can't, so decide them in
the first `vcluster.yaml` you deploy with. The two that matter for most
clusters are the worker node model and the backing store.

A cluster that starts on shared nodes can't move to
[private nodes](../deploy/worker-nodes/private-nodes/overview.mdx) later. For
the [backing store](./control-plane/components/backing-store/overview.mdx),
changing its type by editing the configuration in place isn't supported, apart
from a few documented migrations. To weigh these choices for
production, start with [Plan your cluster](../plan/choose-control-plane-deployment.mdx).
