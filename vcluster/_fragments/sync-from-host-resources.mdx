vCluster can sync certain resources from the control plane cluster to make them available inside the cluster, but when these resources are
synced, they are only synced in read-only mode. No changes to the resource in the cluster syncs back to the control plane cluster as the
resources are shared across the control plane cluster.

A good example would be nodes, which are nice to view inside the cluster and can be also used to enabled certain features such as [scheduling inside the vCluster](../configure/control-plane/advanced/virtual-scheduler.mdx),
but you wouldn't want your cluster to change the node itself. Another benefit of only syncing from the control plane cluster is that vCluster itself only requires read-only RBAC permissions.

vCluster also lets you sync custom resources with the [custom resource syncer](../configure/sync/from-host/custom-resources.mdx)

There are a couple of labels that are created on the control plane cluster by vCluster that never get synced to the cluster resource. These labels are:

* `release` (Label is needed to avoid conflicts with the vCluster pods themselves).
* `vcluster.loft.sh/namespace`
* `vcluster.loft.sh/managed-by`
* `vcluster.loft.sh/controlled-by`
* `vcluster.loft.sh/ns-label-*`
These labels are added as management labels when syncing from the cluster to the control plane cluster, but skipped when syncing from the control plane cluster to the cluster to prevent sync loops.

### Resource creation behavior
#### Cluster-scoped resources
The following resources are not created during sync if they don’t already exist in the cluster:
- [CSINodes](../configure/sync/from-host/csi-nodes.mdx)
- [CSIDrivers](../configure/sync/from-host/csi-drivers.mdx)

The following resources are created in the cluster as read-only if they don't already exist during the sync:
- [Nodes](../configure/sync/from-host/nodes.mdx)
- [IngressClasses](../configure/sync/from-host/ingress-classes.mdx)
- [Gateways and GatewayClasses](../configure/sync/from-host/gateways.mdx)
- [StorageClasses](../configure/sync/from-host/storage-classes.mdx)
- Cluster-scoped [CustomResources](../configure/sync/from-host/custom-resources.mdx)

#### Namespaced resources
Namespaced resources are automatically created in the cluster if they do not already exist. Before synchronization occurs, the mapping between the control plane cluster source namespace name and the corresponding cluster target namespace name must be defined.
This applies to:
- [Events](../configure/sync/from-host/events.mdx)
- [ConfigMaps](../configure/sync/from-host/configmaps.mdx)
- [Secrets](../configure/sync/from-host/secrets.mdx)
- Namespace-scoped [CustomResources](../configure/sync/from-host/custom-resources.mdx)

For CSIStorageCapacities, synchronization occurs only when a corresponding mapping exists between the physical StorageClass name in the control plane cluster and the StorageClass name in the cluster and
the capacity aligns with the associated physical node:
- [CSIStorageCapacities](../configure/sync/from-host/csi-storage-capacities.mdx)

### No bi-directional syncing

Since syncing resources from the control plane cluster is in read only mode and changes in the cluster do not
get applied to the resource in the control plane cluster, bi-directional syncing does not exist across these resources.
