With the breaking changes introduced in v0.20, the vCluster CLI was also updated to match the direction of the project.

There were also two significant CLI changes that influenced the changes in the `vcluster` CLI.

1. The `loft` CLI, which was used to manage the platform (formerly known as loft) was deprecated and no longer supported, so all commands in the `loft` CLI were moved into the `vcluster` CLI.
2. The `vcluster pro` command was renamed to [`vcluster platform`](../../cli/vcluster_platform.md).

With these two significant changes, there were duplicate features from the older CLI (`loft`) and vCluster command (`vcluster pro`) that were merged as `vcluster platform`.

## New commands in v0.20.0

* `vcluster convert` : Converted a pre-v0.20 `values.yaml` to the new `vcluster.yaml` format. This command was removed from the vCluster CLI in v0.32.0. See the [dedicated migration guide](0-20-migration.mdx) for how to convert legacy values files with an older CLI release.

* [`vcluster set`](../../cli/vcluster_set.md) : Set configuration

* [`vcluster use`](../../cli/vcluster_use.md) : vCluster use subcommand - This command allows you to switch between the drivers (Helm or platform).

## Renamed commands from vCluster CLI v0.19.x

* `vcluster import` was renamed to [`vcluster platform add`](../../cli/vcluster_platform_add.md) : Adds a cluster or vCluster to vCluster platform

* `vcluster get` was renamed to [`vcluster platform get`](../../cli/vcluster_platform_get.md) : Retrieves and displays information

## New commands that were used in `vcluster pro` and `loft`

* `loft credits` was renamed to [`vcluster credits`](../../cli/vcluster_credits.md) : Saves the OSS credits

* `loft generate` was replaced with [`vcluster platform create`](../../cli/vcluster_platform_create.md) and [`vcluster platform set`](../../cli/vcluster_platform_set.md)

* `loft import` was renamed to `vcluster platform add` : Adds a cluster or vCluster to vCluster platform


### Changed subcommands

* `vcluster pro token` / `loft token` was renamed to [`vcluster platform access-key`](../../cli/vcluster_platform_access-key.md) 

* `vcluster pro connect` was renamed to [`vcluster platform connect`](../../cli/vcluster_platform_connect.md) with additional context.

* `vcluster pro generate` was removed and replaced with `vcluster platform create` and `vcluster platform set`

### Renamed commands from `loft` CLI to `vcluster platform` CLI

This is a list of commands that were formerly in the `loft` CLI and now renamed in `vcluster` under `vcluster platform`. All features remain the same.

* [`vcluster platform backup`](../../cli/vcluster_platform_backup.md) : Backup subcommands

* `vcluster platform connect` : Connects a cluster to vCluster Platform. 

* `vcluster platform create` : Creates vCluster platform resources

* [`vcluster platform delete`](../../cli/vcluster_platform_delete.md) : Deletes vCluster platform resources

* `vcluster platform get` : Retrieves and displays information

* [`vcluster platform list`](../../cli/vcluster_platform_list.md) : Lists configuration

* [`vcluster platform reset`](../../cli/vcluster_platform_reset.md) : Reset configuration

* `vcluster platform set` : Set configuration

* [`vcluster platform share`](../../cli/vcluster_platform_share.md) : Shares a cluster/namespace with another vCluster platform user or team

* [`vcluster platform sleep`](../../cli/vcluster_platform_sleep.md) : Put a cluster/namespace to sleep

* [`vcluster platform start`](../../cli/vcluster_platform_start.md) : Start a vCluster Platform instance and connect using port-forwarding

* [`vcluster platform wakeup`](../../cli/vcluster_platform_wakeup.md) : Wake up a cluster/namespace



## Flag differences

### New global flag

* [`--config`](../../cli/global-flags.mdx) string : The vCluster CLI config to use (will be created if it does not exist)

### New flags within each command

* [`vcluster connect`](../../cli/vcluster_connect.md)

    * `--driver` string : Specifies the driver to use for managing the cluster (helm or platform).

* [`vcluster create`](../../cli/vcluster_create.md)

    * `--add` : Automatically adds the cluster to the current vCluster platform when using the helm driver (default true).

    * `--background-proxy` : Uses a background-proxy to access the vCluster if docker is installed and reachable (default true).

    * `--create-context` : Creates a kube context for the namespace (default true).

    * `--description` string : Description to show in the platform UI for this cluster. 

    * `--display-name` string : Display name to show in the platform UI for this cluster.

    * `--driver` string : Specifies the driver to use for managing the cluster (helm or platform).

    * `--parameters` string : Uses a file for the parameters if a template is used.

    * `--print` : Prints the context to the console if enabled.

    * `--recreate` : Deletes an existing cluster with the same name before creating a new one.

    * `--set-parameter` stringArray : Sets specific parameters if a template is used.

    * `--skip-wait` : Does not wait until the cluster is running if true. 

    * `--switch-context` : Switches the current context to the new context (default true).

    * `--team` string : Specifies the team to create the namespace for. 

    * `--use` : Uses the cluster if it's already there. 

    * `--user` string : Specifies the user to create the namespace for. 

* [`vcluster delete`](../../cli/vcluster_delete.md)

    * `--delete-context` : Deletes the corresponding kube context if there is any (default true).

    * `--driver` string : Specifies the driver to use for managing the cluster (helm or platform).

* [`vcluster list`](../../cli/vcluster_list.md)

    * `--driver` string : Specifies the driver to use for managing the cluster (helm or platform).

* [`vcluster platform login`](../../cli/vcluster_platform_login.md)

    * `--use-driver` string : Switches the vCluster driver between platform and helm. 

* [`vcluster pause`](../../cli/vcluster_pause.md)

    * `--driver` string : Specifies the driver for the cluster (helm or platform).

* [`vcluster resume`](../../cli/vcluster_resume.md)

    * `--driver` string : Specifies the driver for the cluster (helm or platform).   

### Dropped flags within each command

* `vcluster connect`

    * `--kube-config` string: This flag was used to specify the file to write the created kube config to. The default value was "./kubeconfig.yaml". 

    * `--kube-config-context-name` string: This flag was used to override the context name of the generated cluster kube config with a specified name. 

    * `--update-current`: This flag was used to update the current kube config if set to true. The default value was true. 

* `vcluster create`

    * `--disable-pro`: This flag was used to stop the CLI from creating a Pro cluster. It could also be used with `vcluster logout` to stop the CLI from creating any Pro clusters. In v0.20.0, clusters use the Pro images by default. To use the OSS images, replace the images in `vcluster.yaml`.

    * `--distro` string: This flag was used to specify the Kubernetes distro to use for the cluster. Allowed distros were k3s, k0s, k8s, eks, with the default being "k3s". In v0.20.0, configuring the distro is now in the vcluster.yaml with the default being "k8s".

    * `--extra-values` strings: This flag was deprecated and used to specify extra values. It was replaced by the  --values  flag.

    * `--isolate` : This flag was used to run vCluster and its workloads in an isolated environment. In v0.20.0, running workloads in an isolated environment is [configured within vcluster.yaml](../../deploy/worker-nodes/host-nodes/isolated-workloads.mdx).

    * `--params` string: This flag was used to specify a file for the parameters if a template was used. It was replaced by the  --parameters string  flag.
