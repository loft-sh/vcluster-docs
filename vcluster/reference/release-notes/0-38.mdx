This page lists the customer-facing changes in each vCluster v0.38 release. For
an overview of the release, see [What's new](../../overview/whats-new.mdx).

Some changes also shipped in a v0.37 patch release. Those items name the patch,
so if you already run that patch or later, they don't change anything for you.

## 0.38.0

Released November 18, 2026.

### Upgrade notes

Upgrading to v0.38 is supported only from v0.37. vCluster v0.38 is a limited
availability release, so
[contact vCluster Labs](https://www.vcluster.com/enterprise-demo) before you
upgrade an existing installation. vCluster v0.38 doesn't remove or rename any
`vcluster.yaml` keys. Check these items before you upgrade. If vCluster
Platform manages your clusters, upgrade Platform to v5.0 first.

- Clusters on v0.37.0 or v0.37.1 that use the resource proxy start enforcing
  validating admission policies and webhooks on proxied writes. Server-side
  apply to a proxied resource is refused. These checks shipped in v0.37.2.
- Istio 1.27 and 1.28 are no longer tested. The tested versions are 1.29.0,
  1.30.0, and 1.31.1. See [Istio](../../integrations/istio.mdx).
- In clusters with private nodes, Karpenter resources become read-only once
  vCluster starts its own Karpenter, for example to run a Platform node pool,
  even when `autoNodes` isn't configured. A Karpenter you installed yourself
  keeps working until then.

### Deprecations

- The Istio integration, `integrations.istio`, is deprecated, including sleep
  mode for Istio ingress. It remains available, and no removal date is
  announced. See [Istio](../../integrations/istio.mdx).

### New features

- **Platform node pools.** With Platform v5.0, a cluster reads node pools
  defined in the platform and runs them through Auto Nodes alongside the pools
  in `vcluster.yaml`. Give platform pools names that differ from the pools in
  `vcluster.yaml`. There are no new `vcluster.yaml` keys.
  {/* Link after #3043 merges: /docs/platform/next/vmetal/deploy/node-pools */}
- **Embedded etcd defragmentation timeout.**
  `controlPlane.backingStore.etcd.embedded.defragTimeout` limits startup
  defragmentation, with a default of `5m`. Set `0s` to skip it. See
  [Embedded etcd](../../configure/control-plane/components/backing-store/etcd/embedded.mdx).
- **Docker driver on Podman.** The Docker driver works with rootful Podman
  through its Docker-compatible API. You still need the `docker` CLI, and
  LoadBalancer services aren't available on Podman. On Windows, the CLI
  doesn't find Podman's socket for you, so set `DOCKER_HOST` yourself. See
  [Docker container basics](../../deploy/control-plane/docker-container/basics.mdx).
- **Argo CD cluster metadata.** `integrations.argoCD.cluster.metadata` adds
  labels and annotations to the cluster's Argo CD registration. Also in v0.37.4.
  {/* Link after #3017 merges. */}
- **Observability integration.** `integrations.observability` delivers the
  Platform metrics-writer Secret to the cluster.
  {/* TODO: no docs page yet (DOC-1893). */}
- **ServiceMonitor scrape interval.** `controlPlane.serviceMonitor.interval`
  sets how often Prometheus scrapes the control plane. Also in v0.37.3. See
  [ServiceMonitor](../../configure/control-plane/deployment/service-monitor.mdx).

### Changes

- The default Kubernetes version is 1.36.6. The Kubernetes 1.35 image moves to
  1.35.10, and the default etcd image is `3.6.16-0`. Also in v0.37.5.
  The rebuilt Kubernetes images include upstream security fixes.
- The image lists published with the release include only Kubernetes 1.35 and
  1.36 images. Clusters pinned to an older minor keep working, but mirror those
  images yourself for air-gapped installations. Also in v0.37.5.
- Embedded etcd defragments on startup only when it can reclaim enough space.
  Before v0.38, it defragmented on every start and failed after 30 seconds.
- Auto Nodes removes unscheduled node claims first when it scales down a pool.
  It replaces node claims that haven't joined when a
  pool's configuration changes, and with Platform v5.0 it removes nodes whose
  machine is gone. See [Auto Nodes](../../configure/private-nodes/auto-nodes.mdx).
- A platform restored from a management backup taken with the CLI keeps its
  identity. Also in v0.37.4.

### Fixes

- `vcluster platform destroy` works against vCluster Platform v5.0. Earlier CLI
  versions stopped before deleting anything. See
  [Uninstall the platform](/docs/platform/next/administer/uninstall).
- Restoring a snapshot of an embedded database keeps the store revision moving
  forward, and the restore refuses to run over a live database. Also in v0.37.5.
- `vcluster connect` handles kubeconfig servers without an explicit port, and
  port forwarding drops a path in the kubeconfig server URL.
- Platform node claims work in clusters without Auto Nodes, and a pending node
  claim is deleted when its node pool is removed.
- When a sync fails part way, changes that weren't synced yet are kept instead
  of being overwritten.
- `policies.networkPolicy` allows DNS traffic to the CoreDNS that vCluster
  deploys, for example on vCluster Standalone. Before, it blocked DNS there.
- Dual-stack networking works on vCluster Standalone and private nodes.
  Standalone accepts a dual-stack `networking.podCIDR` and
  `networking.serviceCIDR`, the built-in flannel splits a dual-stack pod CIDR
  by address family, and private nodes with two node IPs initialize.
- Containerd registry credentials that contain `$` are preserved on private
  nodes. Also in v0.37.4.
- Private nodes detect dead konnectivity agent connections. Also in v0.37.4.
- A stopping standalone control plane is removed from the Kubernetes endpoints.
  Also in v0.37.4.
