This section connects a cluster to the tools around it. Most integrations work in one of three ways, and the way decides what you install and where.

- **Reuse a tool on the control plane cluster.** Tools such as cert-manager, External Secrets Operator, Istio, KubeVirt, and the metrics server run once on the control plane cluster. Each cluster's workloads use that installation, so the cluster doesn't need its own copy.
- **Run a tool inside the cluster.** Some tools, such as an inference serving stack, run inside each cluster like any other workload.
- **Automate the cluster itself.** GitOps and CI integrations create clusters from Git or from a pipeline, and can use them as short-lived test environments.

Most pages show which worker node models the integration supports. Free and Enterprise badges in the sidebar mark integrations that need vCluster Platform.

## Platform integrations

vCluster Platform has its own integrations for the management plane. Use [Argo CD](/docs/platform/next/integrations/gitops-cicd/argocd) to deploy apps, or [GitLab CI](/docs/platform/next/integrations/gitops-cicd/gitlab-ci) to create a cluster for each merge request. [HashiCorp Vault](/docs/platform/next/integrations/identity-secrets/hashicorp-vault) syncs secrets, [Karpenter](/docs/platform/next/integrations/autoscaling/karpenter) gives clusters dedicated node pools, and [Certified Stacks](/docs/platform/next/integrations/cluster-workloads/certified-stacks) deploy ready-made workloads.
