This section connects a cluster to the tools around it. Most integrations work in one of three ways, and the way decides what you install and where.

- **Reuse a tool on the control plane cluster.** Tools such as cert-manager, External Secrets Operator, Istio, and KubeVirt run once on the control plane cluster. Each cluster's workloads use that installation, so the cluster doesn't need its own copy.
- **Run a tool inside the cluster.** Some tools, such as an inference serving stack or a dedicated metrics server, run inside each cluster like any other workload.
- **Automate the cluster itself.** GitOps and CI integrations create clusters from Git or from a pipeline, and can use them as short-lived test environments.

Card tags show which worker node models a guide supports, **Shared nodes** or **Private nodes**. A **Free** or **Enterprise** tag means the integration needs a platform license at that tier. See [Open Source vs Free tier](../overview/oss-vs-free.mdx) for what the Free tier includes. Cards tagged **vCluster Platform** lead to the platform docs, where the integration runs in the management plane.

## Infrastructure and fleet management

These integrations cover the infrastructure under your clusters and the tools that manage them as a fleet. KubeVirt appears twice, depending on what the virtual machines are for. The vCluster integration reuses KubeVirt on the control plane cluster, so workloads in a cluster can create virtual machines alongside their pods. The platform node provider creates virtual machines that join a cluster as its worker nodes.
