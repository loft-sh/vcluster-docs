This section connects a cluster to the tools around it. Most integrations work in one of three ways, and the way decides what you install and where.

- **Reuse a tool on the control plane cluster.** Tools such as cert-manager, External Secrets Operator, Istio, KubeVirt, and the metrics server run once on the control plane cluster. Each cluster's workloads use that installation. The cluster doesn't need its own copy.
- **Run a tool inside the cluster.** Some tools run inside each cluster like any other workload, such as an inference serving stack.
- **Automate the cluster itself.** GitOps and CI integrations create clusters from Git or from a pipeline. Some create short-lived clusters for tests.

To see the integrations for vCluster, vCluster Platform, and vMetal in one place, see [all integrations](/docs/integrations).

Card tags show which worker node models a guide supports, **Shared nodes** or **Private nodes**. A **Free** or **Enterprise** tag means the integration needs a platform license at that tier. See [Open Source vs Free tier](../overview/oss-vs-free.mdx) for what the Free tier includes. Tags repeat what each guide states, so a missing tag means the guide doesn't state that requirement.
