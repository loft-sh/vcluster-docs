Use this checklist before a cluster takes production traffic. The items are usually done from top to bottom, but skip any that don't apply to your deployment. Each item links to the guide that owns the procedure.

- [ ] **Choose the worker node model.** Shared or private nodes are fixed at creation, and the choice is a security boundary. See [Choose a worker node model](/docs/plan/choose-worker-node-model).
- [ ] **Use a production backing store.** Replace the default embedded SQLite, which can't run more than one replica. See [Choose a backing store](./choose-backing-store.mdx).
- [ ] **Run three control plane replicas.** See [Size for high availability and scale](./size-for-high-availability-and-scale.mdx).
- [ ] **Set control plane resources.** Start with the P3 profile and adjust for your workload. See [Control plane sizing and performance](../deploy/control-plane/sizing-and-performance.mdx).
- [ ] **Harden the deployment.** Apply the security baseline, and the CIS hardening guide for a pod-based control plane. See [Secure vCluster deployments](../security/README.mdx) and the [hardening guide](../deploy/control-plane/kubernetes-pod/security/hardening-guide/overview.mdx). On shared nodes, also apply [shared-node hardening](../security/shared-nodes-hardening.mdx).
- [ ] **Restrict network traffic.** Enable a default network policy, and confirm the control plane cluster's CNI enforces it. Some CNIs accept NetworkPolicy objects without enforcing them. See [Network policy](../configure/vcluster-yaml/policies/network-policy.mdx).
- [ ] **Schedule backups and test a restore.** Take regular snapshots, then restore one to prove the backup works. Deployed etcd needs etcd's own tooling instead. See [Snapshots](../configure/vcluster-yaml/snapshots.mdx) and [Restore snapshots](../operate/backup-restore/restore.mdx).
- [ ] **Plan upgrades.** Know which versions are supported and how to move between them. See [Upgrade vCluster](../operate/upgrade/upgrade-version.mdx) and the [lifecycle policy](../operate/upgrade/supported_versions.mdx).
- [ ] **Plan certificate rotation.** See [Rotate certificates](../operate/certificates.mdx).
- [ ] **Collect logs and set alerts.** Ship control plane logs somewhere durable, and alert on API latency, errors, and etcd health. See [Logging](../operate/logging.mdx) and the alert thresholds in [Operational guidance](../deploy/control-plane/sizing-and-performance.mdx#operational-guidance).
- [ ] **Know how outages behave.** Understand what tenants see when a control plane or the control plane cluster fails. See [What happens during control plane outages?](./control-plane-outages.mdx).

## Next steps
