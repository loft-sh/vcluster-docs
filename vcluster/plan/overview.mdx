This section is for anyone preparing a cluster for production. Read it before [Deploy](../deploy/overview.mdx). Several of these choices are fixed when the cluster is created, so making them first saves a rebuild later. Each page explains one decision and links to the Deploy or Configure page that carries it out.

## Make the decisions in order

1. [Choose a control plane deployment](./choose-control-plane-deployment.mdx) decides whether the control plane runs as a pod on a Kubernetes cluster, as a Standalone binary on its own nodes, or in Docker.
2. [Decide whether tenants share hardware](/docs/plan/choose-worker-node-model) chooses between shared and private worker nodes. The choice is fixed at creation and sets the tenant isolation boundary.
3. [Choose a backing store](./choose-backing-store.mdx) picks where the cluster stores its state. Changing the type in place isn't supported.
4. [Size for high availability and scale](./size-for-high-availability-and-scale.mdx) sets the replica count, resource profile, DNS capacity, and control plane cluster capacity.
5. [Production readiness checklist](./production-readiness-checklist.mdx) confirms the cluster is ready before it takes production traffic, from hardening to backups and monitoring.

## Understand how a cluster fails

These pages explain behavior to plan around rather than a decision to make.

- **Outages.** [What happens during control plane outages?](./control-plane-outages.mdx) describes how the cluster behaves when its own control plane or the control plane cluster is unavailable.
- **DNS load.** [Why does CoreDNS become a DNS bottleneck?](./coredns-bottlenecks.mdx) explains when a single CoreDNS replica runs out of headroom.
