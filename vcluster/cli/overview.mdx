The vCluster CLI, `vcluster`, creates, connects to, and maintains clusters from
your terminal. This section is its reference. Three pages cover setting the CLI
up, and every other page documents one command, with its flags and examples,
generated from the CLI's own help. If you don't have the CLI yet, start with
[Install the vCluster CLI](./install.mdx).

## How commands reach a cluster

Most commands manage a cluster's lifecycle, and they work through a driver.
[`vcluster use driver`](./vcluster_use_driver.md) sets the default deployment
method to Helm, the platform, or Docker. The lifecycle commands, such as
`create`, `connect`, `list`, `delete`, `pause`, and `restore`, use that default,
and each one takes a `--driver` flag to override it for a single run.

The driver decides what a command does, not only where it runs. Pausing a
cluster with the Helm driver, for example, stops different things than pausing
it through the platform. When a command's effect matters, read the task page
that uses it, such as [Pause and resume a cluster](../operate/sleep-wakeup.mdx).

A few commands don't use a driver at all. `vcluster certs`, `vcluster token`,
and `vcluster node` work on one cluster's control plane certificates, join
tokens, and nodes. The commands under [`vcluster platform`](./vcluster_platform.md)
work with vCluster Platform itself, such as logging in, access keys, and
backups. For those grouped next to their UI equivalents, see the
[Platform CLI hub](/docs/platform/next/reference/platform-cli) in the vCluster
Platform docs.

## Find a command

The table groups the top-level commands by task. Each command page lists its
subcommands.

| Task | Command | What it does |
|------|---------|--------------|
| Set up the CLI | [`vcluster use driver`](./vcluster_use_driver.md) | Sets Helm, the platform, or Docker as the default driver |
| | [`vcluster upgrade`](./vcluster_upgrade.md) | Updates the CLI itself |
| | [`vcluster version`](./vcluster_version.md) | Prints the installed CLI version |
| | [`vcluster telemetry`](./vcluster_telemetry.md) | Turns CLI telemetry on or off |
| | [`vcluster credits`](./vcluster_credits.md) | Saves the license and copyright notices of the CLI's dependencies |
| Create and connect | [`vcluster create`](./vcluster_create.md) | Deploys a cluster from a `vcluster.yaml` you pass with `--values` |
| | [`vcluster connect`](./vcluster_connect.md) | Connects to a cluster and gets a kubeconfig for it |
| | [`vcluster disconnect`](./vcluster_disconnect.md) | Switches your kube context back after a connect that changed it |
| | [`vcluster list`](./vcluster_list.md) | Lists your clusters |
| | [`vcluster describe`](./vcluster_describe.md) | Shows the details of one cluster |
| | [`vcluster delete`](./vcluster_delete.md) | Removes a cluster |
| Run clusters | [`vcluster pause`](./vcluster_pause.md) and [`vcluster resume`](./vcluster_resume.md) | Pause a cluster and start it again. What pause stops depends on the driver |
| | [`vcluster snapshot create`](./vcluster_snapshot_create.md) and [`vcluster snapshot get`](./vcluster_snapshot_get.md) | Request a snapshot of a cluster, and get one from its storage location |
| | [`vcluster restore`](./vcluster_restore.md) | Restores a cluster from a snapshot |
| | [`vcluster certs`](./vcluster_certs.md) | Checks the control plane certificates and rotates the leaf certificates or the CA |
| | [`vcluster debug`](./vcluster_debug.md) | Collects diagnostic information, or opens a shell in the control plane pod |
| Nodes and images | [`vcluster token`](./vcluster_token.md) | Creates, lists, and deletes the bootstrap tokens private nodes use to join |
| | [`vcluster node`](./vcluster_node.md) | Upgrades or deletes a node, and loads a local Docker image into one |
| | [`vcluster registry`](./vcluster_registry.md) | Pushes images, archives, and Helm charts into the cluster's registry |
| The platform | [`vcluster platform`](./vcluster_platform.md) | Holds the commands for vCluster Platform |
| | [`vcluster ui`](./vcluster_ui.md) | Opens the platform web UI |
| | [`vcluster set secret`](./vcluster_set_secret.md) | Sets a key in a project or shared secret |
| | [`vcluster logout`](./vcluster_logout.md) | Logs out of the platform. To log in, use `vcluster platform login`, because `vcluster login` is deprecated |

Two setup pages aren't commands. [Global flags](./global-flags.mdx) covers the
flags every command accepts, such as the kube context, namespace, and log
verbosity. [Use vCluster CLI as a kubectl plugin](./cli-kubectl.mdx) lets you
run the same commands through `kubectl`.

## Commands in context

A command page tells you what a command accepts. The task pages tell you when to
run it and what happens. To run clusters in Docker, see
[Deployment basics](../deploy/control-plane/docker-container/basics.mdx). To
join private nodes, see
[Join manually provisioned nodes](../deploy/worker-nodes/private-nodes/join.mdx).
For kubeconfigs, snapshots, and certificate rotation, see
[Access and expose vCluster](../operate/accessing-vcluster.mdx),
[Create snapshots](../operate/backup-restore/backup.mdx), and
[Rotate certificates](../operate/certificates.mdx).
