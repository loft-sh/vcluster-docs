Pause a <GlossaryTerm term="tenant-cluster">tenant cluster</GlossaryTerm> when you want to stop it on demand and free its compute
resources. Resume it when you need it again. Manual pause doesn't start from an
inactivity timeout or schedule.

For automatic behavior, see [Configure auto sleep](../configure/vcluster-yaml/sleep.mdx).

## Prerequisites

<BasePrerequisites />

- vCluster CLI
  <InstallCli />

## Pause a tenant cluster

Run the following command against the Kubernetes context that contains the
tenant cluster:

```bash title="Pause a tenant cluster"
vcluster pause <vcluster-name> --namespace <vcluster-namespace>
```

The command uses the driver in the vCluster CLI configuration. The default is
`helm`. Select a different driver with `--driver`; supported values are `helm`,
`platform`, and `docker`.

For a platform-managed tenant cluster, you can identify it by project instead:

```bash title="Pause a platform-managed tenant cluster"
vcluster pause <vcluster-name> --driver platform --project <project-name>
```

With the Platform driver, add `--prevent-wakeup <seconds>` to prevent automatic
wakeup for a period. Use `--prevent-wakeup 0` to require an explicit wakeup
through the CLI or Platform UI. This flag doesn't apply to the Helm or Docker
drivers. Without this flag, Kubernetes API requests routed through the platform
and supported HTTP traffic can wake the tenant cluster.

:::tip CLI reference
See the [`vcluster pause` CLI reference](../cli/vcluster_pause.md) for all flags.
:::

### What pause changes

The effect of pause depends on the deployment driver:

- The Helm driver scales down the tenant cluster <GlossaryTerm term="control-plane">control plane</GlossaryTerm> and deletes its
  synced physical workload Pods from the <GlossaryTerm term="control-plane-cluster">control plane cluster</GlossaryTerm>.
- The Platform driver puts the tenant cluster instance to sleep. The platform
  can scale down both its control plane and physical workloads.
- The Docker driver stops the tenant cluster control plane, node, and load
  balancer containers.

The tenant cluster's Kubernetes API objects remain, and PersistentVolumeClaims,
Services, and other non-workload resources aren't deleted by pause. With the
Helm and Platform drivers, resume recreates physical workload Pods the same way
as [platform-managed auto sleep](../key-features/sleep.mdx#what-happens-during-platform-managed-auto-sleep),
including Pods without a Kubernetes workload controller.

## Resume a tenant cluster

Resume a paused tenant cluster with the same name and deployment context:

```bash title="Resume a tenant cluster"
vcluster resume <vcluster-name> --namespace <vcluster-namespace>
```

For a platform-managed tenant cluster identified by project, run:

```bash title="Resume a platform-managed tenant cluster"
vcluster resume <vcluster-name> --driver platform --project <project-name>
```

With the Helm or Platform driver, you can also connect to a paused tenant
cluster. Unless wakeup is currently prevented, the connection resumes the
tenant cluster automatically.

For the Helm driver, run:

```bash title="Connect and resume"
vcluster connect <vcluster-name> --namespace <vcluster-namespace>
```

For the Platform driver, run:

```bash title="Connect to and resume a platform-managed tenant cluster"
vcluster connect <vcluster-name> --driver platform --project <project-name>
```

The Docker driver requires `vcluster resume` before `vcluster connect`.

:::tip CLI reference
See the [`vcluster resume` CLI reference](../cli/vcluster_resume.md) for all flags.
:::

## Manual pause compared with auto sleep

| Capability | Manual pause | Auto sleep |
| --- | --- | --- |
| Start condition | CLI command | Inactivity timeout, schedule, or manual action |
| Automatic wakeup from activity | Helm: CLI connection. Platform: platform-proxied API, supported HTTP traffic, or CLI connection. Docker: none. | Inactivity sleep: Kubernetes API or supported HTTP traffic. Platform-scheduled sleep waits for its wakeup schedule or a manual wakeup. |
| Scheduled sleep and wakeup | No | Yes |
| Auto-delete after inactivity | No | Platform-managed only |

See [Sleep tenant clusters](../key-features/sleep.mdx) for an overview of the
available sleep methods.
