This section covers working with a cluster after it's already running. [Deploy](../deploy/overview.mdx) decides how the cluster is built, and [Configure](../configure/what-is-vcluster-yaml.mdx) turns its capabilities on or tunes them in `vcluster.yaml`.

Operate work splits into tasks you repeat and changes you plan ahead.

## Routine tasks

These are the tasks most cluster users come back to.

- **Connect.** [Access and expose](./accessing-vcluster.mdx) gets you a kubeconfig through the vCluster CLI or a service account, and exposes the cluster outside the control plane cluster.
- **Pause idle clusters.** [Sleep](./sleep.mdx) compares manual pause with the two kinds of auto sleep, so you can pick one before you set it up.
- **Apply configuration changes.** [Deploy config changes](./deploy-changes.mdx) rolls an updated `vcluster.yaml` out to a running cluster.
- **Back up and restore.** [Create snapshots](./backup-restore/backup.mdx) saves a cluster's state, and [Restore snapshots](./backup-restore/restore.mdx) brings it back.
- **Read logs.** [Logging](./logging.mdx) explains the kinds of logs vCluster produces and where to find each one.

When something goes wrong, see [Troubleshoot](../troubleshoot/overview.mdx).

## Planned changes

Some changes to a running cluster are done infrequently and planned ahead. They include [upgrading vCluster](./upgrade/upgrade-version.mdx), [rotating the CA certificate](./certificates.mdx), and [moving from ingress-nginx to Gateway API](./ingress-nginx-to-gateway-api.mdx). For the backing store, you can [upgrade etcd to v3.6](./upgrade/safely-upgrade-etcd.mdx) or [migrate from deployed to embedded etcd](./migrate-etcd-backing-store.mdx). Clusters still on K3s must [move to Kubernetes](./upgrade/distro-migration.mdx) before upgrading to vCluster 0.33 or later.

Each has its own prerequisites, so read the page through before you start. Back up the cluster first.
