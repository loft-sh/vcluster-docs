Configure this when you want vCluster to deploy an Ingress resource to expose the cluster's API server at a hostname. The cluster must have an ingress controller running and a LoadBalancer Service.

:::warning ingress-nginx is deprecated
The upstream ingress-nginx project is deprecated. Existing ingress-based configurations continue to work in vCluster v0.35 and vCluster Platform v4.10, but Gateway API is recommended for new endpoint deployments. See [Gateway API](../../networking/gateway-api.mdx) and [Migrate from ingress-nginx to Gateway API](../../../operate/ingress-nginx-to-gateway-api.mdx).
:::

This feature is not the same as syncing Ingress resources between the control plane cluster and clusters. See [sync.fromHost.ingressClasses](../../sync/from-host/ingress-classes.mdx) and [sync.toHost.ingresses](../../sync/to-host/networking/ingresses.mdx).

vCluster uses a default rule, which uses the `ingress.host` and `ingress.pathType` configuration.  When configure `ingress.spec.rules`, vCluster ignores `ingress.host` and `ingress.pathType`.

## Config reference

For every field under `controlPlane.ingress`, see the [`controlPlane` reference](../../../reference/vcluster-yaml/control-plane.mdx#controlPlane-ingress).
