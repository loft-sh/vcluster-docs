By default, this is disabled. 

Sync [ServiceAccount](https://kubernetes.io/docs/concepts/security/service-accounts/) resources from the cluster to the control plane cluster.

This is useful for using [AWS IAM roles for service accounts](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html) with the cluster. In this scenario, the control plane cluster is defined as the identity provider to access your OIDC-compatible system, which means you don't have to configure each cluster as a provider. vCluster creates a control plane cluster ServiceAccount token for your synchronized ServiceAccount from the cluster.

:::warning Synced ServiceAccount names are rewritten
vCluster renames the ServiceAccount when it syncs it, to `NAME-x-NAMESPACE-x-VCLUSTER_NAME`. Names longer than 63 characters are truncated and given a hash suffix. Cloud IAM trust policies must reference the rewritten name, so build it with the Platform API rather than hard-coding it.

See [Resource name length and truncation](../../README.mdx#resource-name-length-and-truncation) for the rule, and [Integrate EKS Pod Identity with vCluster](../../../../../third-party-integrations/pod-identity/eks-pod-identity.mdx) for a worked example.
:::

### Sync ServiceAccounts from the tenant to control plane cluster

```YAML
sync:
  toHost:
    serviceAccounts:
      enabled: true
```
