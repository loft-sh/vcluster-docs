The `policies` section of `vcluster.yaml` sets limits and rules for the cluster's workloads.

- [Network policy](./network-policy.mdx) isolates the cluster's traffic from other clusters and the control plane cluster.
- [Pod security standard](./pod-security-standard.mdx) applies a [Pod Security Standards](https://kubernetes.io/docs/concepts/security/pod-security-standards/) level to the cluster's pods.
- [Resource quota](./resource-quota.mdx) caps the compute, storage, and object counts the cluster can use.
- [Limit range](./limit-range.mdx) sets default and maximum CPU, memory, and storage per pod or container.
- [Central admission control](./admission-control.mdx) runs [admission webhooks](https://kubernetes.io/docs/reference/access-authn-authz/extensible-admission-controllers/#admission-webhooks) on the control plane cluster.
  - The admission controller is typically running on the control plane cluster, where the policies enforced by the webhook cannot be changed by the cluster.
  - Users could deploy their own admission webhooks to the cluster, but there's little value in doing so, and this configuration is not concerned with that use case.
  - Some examples of admission controller projects:
    - [OPA](https://www.openpolicyagent.org/docs/latest/)
    - [Kyverno](https://kyverno.io/)
    - [jsPolicy](https://www.jspolicy.com/)
  - It's common for organizations to develop an in-house collection of policies that can enforce naming standards and so on.

You can use these settings separately for specific cases, or together, as in the case of Isolated Mode.
