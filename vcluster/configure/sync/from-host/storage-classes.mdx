StorageClass resources define how clusters provision storage. They specify storage backends such as AWS EBS, Azure Disk, or GCP Persistent Disk, along with parameters such as performance tiers and replication settings.

By default, `sync.fromHost.storageClasses.enabled` is `auto`. It turns on only when the virtual scheduler is enabled, PersistentVolumeClaim sync is on, and StorageClass sync to the control plane cluster is off. Otherwise it stays off.

Even with this sync off, a PersistentVolumeClaim keeps its StorageClass name when vCluster syncs it to the control plane cluster. Tenants can therefore use any StorageClass on the control plane cluster by name, and a claim without a class gets the control plane cluster's default class. Syncing StorageClass resources makes them visible in the cluster, and a selector limits which ones tenants can use.

You can enable this feature to sync StorageClass resources from the control plane cluster to the cluster. Add labels to StorageClass resources in your control plane cluster and configure vCluster to sync only those matching specific selectors. When you create a PersistentVolumeClaim that references a synced StorageClass, the control plane cluster uses that storage configuration. Common use cases include:

- **Cost control**: Restrict access to specific storage classes based on cost or performance characteristics.
- **Compliance**: Control which storage backends and configurations are available to clusters.
- **Tenant isolation**: Provide different storage options to different teams while preventing access to restricted storage types.
- **Simplified management**: Update storage class configurations in the control plane cluster rather than in each cluster.
- **Security**: Control access to storage backends and encryption options.
