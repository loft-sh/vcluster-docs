By default, this is disabled. 

Sync [PriorityClass](https://kubernetes.io/docs/concepts/scheduling-eviction/pod-priority-preemption/#priorityclass) resources from the cluster to the control plane cluster.

Enable this feature if you need to configure the host scheduler to use a certain PriorityClass that is created within the cluster when scheduling the cluster workloads.

When enabled, will update the vCluster control plane's ClusterRole to include the necessary permissions.

:::warning Cross-tenant preemption on shared nodes
On shared nodes, a synced PriorityClass can preempt or starve co-tenant workloads on the same nodes. PriorityClass affects scheduling across the whole control plane cluster, not just the cluster it came from. Leave this disabled unless required. If you enable it, constrain synced values through control plane cluster admission rather than trusting tenant-supplied values. See [operational hardening and lifecycle](../../../../deploy/security/shared-nodes-hardening.mdx#operational-hardening-and-lifecycle).
:::

### Sync PriorityClasses from the tenant to control plane cluster

```YAML
sync:
  toHost:
    priorityClasses:
      enabled: true
```

## Config reference

For every field under `sync.toHost.priorityClasses`, see the [`sync` reference](../../../../reference/vcluster-yaml/sync.mdx#sync-toHost-priorityClasses).
