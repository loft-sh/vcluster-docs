vCluster v0.38 makes control planes more reliable to run and pairs with vCluster
Platform v5.0, which adds Tenants and a shared machine inventory. This page
covers the main changes. For the full list, see the
[vCluster v0.38 release notes](../reference/release-notes/0-38.mdx).

## Serve customers on dedicated machines

With Platform v5.0, a provider gives each customer a Tenant and grants it
dedicated machines. Clusters in that Tenant use Auto Nodes to draw private
nodes from those machines. Node pools that an administrator defines in the
platform now run through Auto Nodes alongside the pools in `vcluster.yaml`. In
0.38, Auto Nodes also replaces node claims that never joined when a pool's
configuration changes, and removes nodes whose machine is gone.

- [What's new in Platform v5.0](/docs/platform/next/overview/whats-new)
- [Auto Nodes](../configure/private-nodes/auto-nodes.mdx)

## Start control planes reliably

Embedded etcd defragments on startup only when it can reclaim space, and you
can set how long defragmentation may take with `defragTimeout`. Restoring a
snapshot of an embedded database keeps the store revision moving forward, a
fix that also shipped in 0.37.5. The syncer keeps unsynced changes when a sync
fails part way.

- [Embedded etcd](../configure/control-plane/components/backing-store/etcd/embedded.mdx)
- [Restore a cluster](../operate/backup-restore/restore.mdx)

## Stay patched and enforce policy

The default Kubernetes version is 1.36.6, as it is from 0.37.5. Rebuilt
Kubernetes images include upstream security fixes.

The resource proxy enforces the cluster's validating admission policies and
webhooks on proxied resources, so the policies that guard the cluster also
guard what the proxy writes.

- [Resource proxy](../overview/resource-synchronization/resource-proxy.mdx)

## Run locally on Podman

The Docker driver works with Podman through its Docker-compatible API, so you
can run a cluster on a machine that runs Podman instead of the Docker daemon.
You still need the `docker` CLI.

- [Docker container basics](../deploy/control-plane/docker-container/basics.mdx)

## Target clusters from Argo CD

`integrations.argoCD.cluster.metadata` adds your own labels and annotations to
the cluster's Argo CD registration, so ApplicationSet cluster generators can
select it. This key also shipped in 0.37.4.

## Availability

Some of these changes need a vCluster license or vCluster Platform v5.0.

| Change | Requires |
|--------|----------|
| Platform node pools, Auto Nodes changes | vCluster Platform v5.0 |
| `defragTimeout`, startup defragmentation changes | Embedded etcd, which needs the Free tier or higher, or vCluster Standalone |
| Admission checks on proxied resources | vCluster Platform, because the resource proxy is a Platform feature |
| Argo CD cluster metadata | vCluster Platform with the Argo CD integration |
| Observability integration | vCluster Platform v5.0 with an observability connector |
| Kubernetes 1.36.6, Podman | Available in every edition |

## Upgrade to 0.38

Upgrading to 0.38 is supported only from 0.37. vCluster v0.38 is a limited
availability release, so
[contact vCluster Labs](https://www.vcluster.com/enterprise-demo) before you
upgrade an existing installation. vCluster v0.38 deprecates the Istio
integration. See the upgrade notes and deprecations in the
[vCluster v0.38 release notes](../reference/release-notes/0-38.mdx).
