Troubleshooting guides are grouped by the part of the cluster where the problem starts. If you know the symptom, jump to its subsystem below. If you don't, start with diagnostics.

- [Control plane](#control-plane)
- [Worker nodes](#worker-nodes)
- [Network](#network)
- [Storage](#storage)
- [Synchronization](#synchronization)

## Start with diagnostics

If you don't know where the problem is yet, collect evidence first. The guides in the Diagnostics group narrow most problems down to one of the subsystems that follow.

1. [Validate your kubecontext](./diagnostics/check-vcluster.mdx) to confirm whether you're connected to the cluster or to the control plane cluster.
2. [Retrieve the deployed vCluster configuration](./diagnostics/retrieve-vcluster-config.mdx) to check what's running against what you expect.
3. [Enable debug logging](./diagnostics/enable-debug-logging.mdx) in the control plane to see what the syncer does.
4. [Capture pprof profiles](./diagnostics/capture-pprof-vcluster.mdx) when the control plane is slow or uses too much CPU or memory.

For where each kind of log lives, see [Logging](../operate/logging.mdx).

## Control plane

The control plane doesn't start, restarts, stops accepting changes, or reports a license error.

- [etcd NOSPACE alarm](./control-plane/etcd-compaction.mdx) when etcd reports `NOSPACE` and the control plane stops accepting changes.
- [etcd defragmentation timeout](./control-plane/etcd-defrag-timeout.mdx) when the control plane fails to start because embedded etcd can't defragment in time.
- [Pro feature license errors](./control-plane/pro-feature-license-error.mdx) when the control plane crashloops with a `vCluster pro feature` error.
- [Standalone control plane nodes](./control-plane/standalone.mdx) when a vCluster Standalone node has service, network, join, or resource problems.

## Worker nodes

Nodes that no longer match the cluster's configuration still show up in it.

- [Clean obsolete nodes](./worker-nodes/clean-up-orphaned-synced-nodes.mdx) when old nodes remain after you change the node selector.

## Network

DNS lookups fail, or connections through Ingress or a load balancer break.

- [CoreDNS DNS timeouts](./networking/coredns-dns-timeouts.mdx) when DNS lookups time out or return `SERVFAIL`.
- [kubectl port-forward and Ingress](./networking/kubectl-port-forward-ingress-issues.mdx) when `kubectl port-forward` fails with connection upgrade errors.
- [Ingress conflicts with Rancher](./networking/resolve-rancher-ingress.mdx) when Rancher runs in both the cluster and the control plane cluster.

## Storage

The vCluster pod can't run binaries from its volumes.

- [noexec emptyDir volumes](./storage/noexec-emptydir-volumes.mdx) when the vCluster pod fails to start with `permission denied` because emptyDir volumes are mounted `noexec`.

## Synchronization

Resources don't appear on the other side, or the syncer reports errors about them.

- [Gateway API sync](./synchronization/gateway-api-sync.mdx) when Gateway API resources emit `RefNotPermitted`, `SyncError`, or `SyncWarning` events.
- [Pods stuck at Ready=False](./synchronization/pod-stuck-ready-false-version-skew.mdx) on vCluster versions before v0.37.0, when the cluster runs Kubernetes 1.33 or earlier and the control plane cluster runs 1.34 or later.
- [Resource proxy](./synchronization/resource-proxy.mdx) when proxied custom resource requests return 4xx or 5xx errors, hang, or don't appear.
