vCluster provisions isolated clusters, delivering managed Kubernetes, Slurm, inference, Ray, and other cluster types. The clusters can go on your existing infrastructure, or they can be built from scratch on bare metal and VMs. Each tenant gets a full Kubernetes API experience while the virtualized control plane stays completely invisible to them.

## Get a cluster running

:::tip Planning a customer-facing or production platform?
These quick starts prove the deployment mechanics. They don't select a production security architecture. [Choose a worker node model](/docs/plan/choose-worker-node-model) first.
:::

## Match your situation to a guide

- Plan a complete service for your tenants, beyond a running cluster → <ServiceLinks />
- Build a production Kubernetes platform from bare metal or VMs → [Standalone](./standalone.mdx)
- Use an existing cluster for a GPU cloud, AI inference service, or regulated platform that needs dedicated infrastructure per tenant → [Private Nodes](./private-nodes.mdx)
- Use an existing Kubernetes cluster for internal platforms, CI, testing, or development with trusted teams → [Shared Nodes](./shared-nodes.mdx)
- Create a Kubernetes cluster on Docker for local development or CI → [Docker (vind)](./docker.mdx)

Still unsure? Read [What is vCluster?](../introduction/what-is-vcluster.mdx) to understand the deployment models and tradeoffs.
