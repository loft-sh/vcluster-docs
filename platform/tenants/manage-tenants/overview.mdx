A Tenant is a customer organization inside vCluster Platform. It sits above
projects, and it's the boundary a platform admin uses to decide what one
customer can see and provision.

[Understand the Tenant model →](../../understand/what-are-tenants.mdx)

## When to use Tenants

Reach for Tenants when more than one organization shares your platform and those
organizations shouldn't see each other.

- **AI cloud operators** selling capacity. Each customer becomes a Tenant, and
  the boundary decides which node types, images, and clusters they can reach.
- **Enterprises** running a platform for separate business units or
  subsidiaries, where each unit administers itself.
- **Anyone delegating administration.** A tenant admin manages their own users,
  projects, and quotas without seeing the rest of the platform.

Tenants are optional. A platform with none behaves exactly as it did before, so
a single internal platform with one trusted admin group doesn't need them.

## Requirements

Tenants require the **Multi-Tenancy** feature in your vCluster Platform license.
Check **Platform > Platform Config > License and Billing** to confirm it's active.

Two license limits apply when a platform admin creates a Tenant.

- The **Tenants** limit caps how many Tenants the platform can hold.
- The **Users** limit is checked as well, because creating a Tenant always
  creates its admin user.

Both are checked on create only. Reaching either limit still leaves existing
Tenants editable.

## Current limitations

The following aren't supported yet. Plan around them rather than working around
them.

| Not supported | What to do instead |
|---------------|--------------------|
| Tenants registering their own [control plane clusters](../../understand/what-are-clusters.mdx) | A platform admin registers the cluster and grants it to the Tenant |
| Tenants authoring their own [templates](../../understand/what-are-templates.mdx) | A platform admin creates templates and grants them by label |
| Tenants creating their own [stacks](../../understand/what-are-stacks.mdx) | A platform admin creates stack templates and grants them |
| Per-tenant [SSO](../../configure/platform-configs/single-sign-on.mdx) | Tenant users sign in through the platform's identity provider |
| Tenant quotas on anything but NICo node types | Cap the rest at project level, which the tenant admin controls |
