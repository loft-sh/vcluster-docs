This section is for the admins who decide what project users can create. A platform admin sets up tenants, and a tenant admin organizes the projects inside one. Project users then create clusters in those projects, which [Use the platform](../use-platform/overview.mdx) covers.

## How the boundaries nest

Each role hands a narrower boundary to the next. The [roles and scopes](/docs/plan/roles-and-scopes) page covers every role and what it can do.

- **Tenant.** A customer organization. A platform admin creates it and grants it the inventory it may use.
- **Project.** A policy boundary inside a tenant. A tenant admin divides the tenant's grant across projects, each with its own members, quotas, and allowed resources.
- **Services.** Templates, Stacks, apps, and project secrets decide what project users can create in a project and how it's configured.

Tenants are optional. On a platform without them, projects are the outermost boundary. For the full model, see [What are tenants](./concepts/what-are-tenants.mdx), [What are projects](./concepts/what-are-projects.mdx), and [What are users and teams](./concepts/what-are-users-and-teams.mdx).

## Set up tenants

These tasks belong to the platform admin.

- **Decide whether you need tenants.** The [tenants overview](./manage-tenants/overview.mdx) explains when to use them and which license limits apply.
- **Create a tenant.** [Create and configure a tenant](./manage-tenants/create-and-configure-tenants.mdx) grants it inventory, assigns dedicated resources, and hands it to a tenant admin.
- **Give it its own look.** [Brand a tenant](./manage-tenants/brand-a-tenant.mdx) sets the logo and colors its users see.
- **Bring in existing resources.** [Move existing resources into tenants](./manage-tenants/move-existing-resources.mdx) moves projects, users, and inventory from Platform v4.12.
- **Look up the boundary.** The [tenant boundary reference](./manage-tenants/tenant-boundary-reference.mdx) shows how each resource behaves inside a tenant.

## Organize projects

A tenant admin does this inside a tenant. On a platform without tenants, a platform admin does it.

- **Create projects.** [Create a project](./projects/create.mdx) adds a project. Each tenant starts with one default project.
- **Choose what a project can use.** Allowed [clusters](./projects/allowed/clusters.mdx), [templates](./projects/allowed/templates.mdx), [node types](./projects/allowed/node-types.mdx), [node profiles](./projects/allowed/node-profiles.mdx), and [network environments](./projects/allowed/network-environments.mdx) limit what members can reach.
- **Cap usage.** [Manage quotas](./projects/quotas.mdx) limits what a project, user, or team can use. [Enforce storage quotas per cluster](./projects/enforce-storage-quotas.mdx) adds per-cluster storage limits.

## Control access

- **Understand roles.** [Role-based access control](./users-permissions/overview.mdx) explains how roles grant access and how tenants and projects narrow them.
- **Manage users and teams.** [Create users](./users-permissions/managing-users/create.mdx) and [create teams](./users-permissions/managing-teams/create.mdx). The Users pages also cover impersonating, suspending, and resetting passwords.
- **Grant access.** [Project membership](./users-permissions/permissions/project.mdx) is the usual way to give access. Other pages cover [direct access to a control plane cluster](./users-permissions/permissions/cluster.mdx), [access to a cluster and the roles users get inside it](./users-permissions/permissions/vcluster.mdx), [namespace access](./users-permissions/permissions/namespace.mdx), and [Stack permissions](./users-permissions/permissions/stacks.mdx).
- **Define roles on control plane clusters.** [Cluster roles](./users-permissions/cluster-roles.mdx) creates Kubernetes cluster roles on connected control plane clusters, which you assign to users and teams through cluster access. It doesn't define roles inside the clusters project users create. For those, see [Custom ClusterRoles](./users-permissions/permissions/vcluster.mdx#custom-clusterroles).

## Offer services

- **Set a baseline.** [What are templates](./templates/overview.mdx) explains how templates govern the clusters, namespaces, apps, and Stacks that members create. Then [create a template](./templates/create-templates.mdx), add [parameters](./templates/parameters.mdx), and [version](./templates/versioning.mdx) it.
- **Deploy several apps as one unit.** [What are Stacks](./templates/what-are-stacks.mdx) explains dependency-aware deployment. [Create a Stack template](./templates/create-stack-templates.mdx), or start from a [certified Stack](./templates/certified-stacks.mdx).
- **Package an app.** [What are apps](./templates/what-are-apps.mdx) explains apps, and [private Helm repositories](./templates/external-credentials.mdx) covers charts that need credentials.
- **Share secrets.** [Create project secrets](./secrets/project/create.mdx) defines secret data once and syncs it into a project's namespaces and clusters.
