Members are users or teams that are granted access to a project. Each member is assigned a role that
define their permissions. These roles will be granted to each of the [allowed clusters](../../projects/allowed/clusters.mdx) of the
project. Only users and teams that are members of the project have access to the project's
allowed clusters.

If you don't have a project, [create one](../../projects/create.mdx).

## Project Roles

There are 3 default roles available for every project.

| Name           | Create New Spaces / Clusters | Access Spaces / Clusters        | Create Without Template | Create With Template | Access to Project Secrets                           |
| -------------- | ------------------------------------ | --------------------------------------- | ----------------------- | -------------------- | --------------------------------------------------- |
| Project admin  | Yes                                  | All Spaces and Clusters         | Yes                     | Yes                  | Yes                                                 |
| Project User   | Yes                                  | Only owned and with explicit permission | No                      | Yes                  | Yes                                                 |
| Project Viewer | No                                   | Only with explicit permission           | No                      | No                   | Only in Spaces and Clusters with permission |

Global admins can change these existing roles as well as add new project roles in the Users section of the platform.
<Flow id="project-add-project-role">
  <Step>
    Go to <NavStep>Platform > Users & Roles</NavStep>.
  </Step>
  <Step>
    In the Users page, click the <NavStep>Global Roles</NavStep> at the top. Then click the <NavStep>Create Role</NavStep>.
  </Step>
  <Step>
    Fill the display name of the role and other information if necessary.
:::warning
The created role will be a global role by default. To create the role as a project role, add the `loft.sh/project-role: 'true'` in the labels of the role resource configuration on the right side of the page.
```yaml title="Add the project role configuration"
apiVersion: management.loft.sh/v1
kind: ClusterRoleTemplate
metadata:
  name: ''
  labels:
    loft.sh/project-role: 'true'
spec:
  management: true
```
    :::
  </Step>
  <Step>
    Click the <NavStep>Create Role</NavStep> button at the right bottom of the page.
  </Step>
  <Step>
    If you created a project role, click <NavStep>Project Config</NavStep> and find the display name of the created project role in the role selector for each member under the <Label>Members and Roles</Label> section.
  </Step>
</Flow>

## Users

Any user can be made members of a project. Follow the instructions below to add and assign roles to users, or
remove them from the project.

### Add users

<Flow id="project-add-user">
  <Step>
    Select the project from the project selector, then click <NavStep>Project Config</NavStep>.
  </Step>
  <Step>
    In the <Label>Members and Roles</Label> section, click <Button>Add User or Team to Project</Button>.
  </Step>
  <Step>
    Search for the user and select it. The user appears in the members table.
  </Step>
  <Step>
    In the user's row, choose a role from the <Label>Role</Label> selector.
  </Step>
  <Step>
    Click <Button>Save changes</Button>.
  </Step>
</Flow>

:::note Everybody
Instead of adding every user, select <Label>Everybody</Label> to add a wildcard member, a user named `*`. A wildcard member covers every identity in the project's own scope, not every identity on the platform.

- On a tenant's project, it covers that tenant's users and team access keys.
- On a project no tenant owns, it covers the platform's users and team access keys, and no tenant's.

A team named `*`, shown as <Label>All teams</Label>, covers the same identities. Users and teams created later are covered from their first request, without a change to the project. Use this option with caution, because every new identity in the scope gets the member's role. See [Project membership](../../concepts/what-are-users-and-teams.mdx#project-membership).
:::

### Remove users

<Flow id="project-remove-user">
  <Step>
    Select the project from the project selector, then click <NavStep>Project Config</NavStep>.
  </Step>
  <Step>
    In the <Label>Members and Roles</Label> section, click the <Label>Remove member</Label> icon in the user's row.
  </Step>
  <Step>
    Click <Button>Save changes</Button>.
  </Step>
</Flow>

## Teams

Instead of assigning individual users, add a team to give all its members access to a project.

### Add teams

<Flow id="project-add-team">
  <Step>
    Select the project from the project selector, then click <NavStep>Project Config</NavStep>.
  </Step>
  <Step>
    In the <Label>Members and Roles</Label> section, click <Button>Add User or Team to Project</Button>.
  </Step>
  <Step>
    Search for the team and select it. The team appears in the members table.
  </Step>
  <Step>
    In the team's row, choose a role from the <Label>Role</Label> selector.
  </Step>
  <Step>
    Click <Button>Save changes</Button>.
  </Step>
</Flow>

### Remove teams

<Flow id="project-remove-team">
  <Step>
    Select the project from the project selector, then click <NavStep>Project Config</NavStep>.
  </Step>
  <Step>
    In the <Label>Members and Roles</Label> section, click the <Label>Remove member</Label> icon in the team's row.
  </Step>
  <Step>
    Click <Button>Save changes</Button>.
  </Step>
</Flow>
