Allowed clusters control the clusters which project members are granted access.

:::warning Unset and empty mean opposite things here and on a Tenant
Where the project belongs to a Tenant, both layers apply and a project member only reaches
what both permit. The two use different mechanisms, so writing "nothing" means opposite
things:

| Layer | Field | Unset or `null` | Empty |
|-------|-------|-----------------|-------|
| Project | `allowedClusters`, a list of names | Everything is allowed | Nothing is allowed |
| Tenant | `allow.byLabels`, a label selector | Nothing is granted | Everything is granted |

A name list narrows a default of everything. A label selector is a conjunction, so an empty
one is vacuously true and matches every instance. Both follow their own convention, and the
result is that an allow-list set here has no effect on inventory the Tenant was never
granted. See [Tenant boundary reference](../../tenants/tenant-boundary-reference.mdx).
:::

### Add allowed clusters

<Flow id="create-vcluster-template-ui">
  <Step>
    Select the project you'd like to configure using the project selector dropdown. Click on <Label>Settings</Label>.
  </Step>
  <Step>
    Click on <NavStep>Control Plane Clusters</NavStep>.
  </Step>
  <Step>
    Click on the input and select the cluster names to allow. If you wish to change this manually, you may edit the YAML directly.
  </Step>
  <Step>
    Once all project options have been specified, click the{" "}
    <Button>Save Changes</Button>.
  </Step>
</Flow>

:::note All Clusters
Instead of selecting every cluster, a special selection named `All Clusters` can be used to give access to all clusters to
the project. Use this option with caution.
:::
