Clusters on shared nodes require the HostPath Mapper for log collection. Log collectors such as Fluentd, the ELK stack, or Grafana Loki mount node host paths and use log filenames to match logs to pods. vCluster renames pods when it syncs them to the control plane cluster, so these collectors can't match the log files to the cluster's pods on their own. The HostPath Mapper creates symbolic links that map each cluster's pod and container names to their names on the control plane cluster.

The per-cluster HostPath Mapper runs a DaemonSet in each cluster's namespace. This setup works well for small environments with few nodes and clusters.

As the number of nodes and clusters grows, the number of required DaemonSet pods also grows. Each cluster's DaemonSet runs a pod on every node, which increases resource usage.

The Central HostPath Mapper solves this problem. It installs a single DaemonSet on the control plane cluster. This DaemonSet manages host path remapping for all clusters on the platform. It reduces overhead and simplifies cluster management.

:::warning Shared nodes only
The HostPath Mapper, central or per cluster, works only for clusters on [shared nodes](/docs/vcluster/next/overview/architecture#shared-nodes), where tenant pods run on control plane cluster nodes.
:::

:::info Prerequisites
To use this feature, install the Central HostPath Mapper on the control plane cluster. The component is available as a default **vCluster Platform App** in the **Apps** section. Install it before enabling the feature to ensure full capabilities are available.
:::

:::warning Templates
This feature is only configurable from the UI for clusters created without a template. When using a custom template that has the feature enabled, the UI doesn't display the configuration in **Advanced Control Plane** as described below. In this case, configure the feature using the CLI or by modifying the manifests.
:::

<Tabs
  defaultValue="creation"
  values={[
    { label: "During cluster creation", value: "creation" },
    { label: "On an existing cluster", value: "existing" },
  ]}
>
  <TabItem value="creation">
    <Flow id="enable-central-hpm-virtualcluster-creation">
      <Step>
        From the project drop-down menu, click the project where you want to
        create the cluster.
      </Step>
      <Step>
        Click the <Button>New Cluster</Button> button above the list of clusters.
      </Step>
      <Step>
        <b>[Optional]</b> Click the control plane cluster where you want to create the
        cluster.
      </Step>
      <Step>
        Leave the <Label>Select a template</Label> section blank and click the <Button>Configure</Button> to continue.
      </Step>
      <Step>
        Go to the <Label>Advanced Control Plane</Label> section and find
        **Host Path Mapper**.
      </Step>
      <Step>
        Turn on <Label>Enable host path mapper</Label>. This adds the
        `loft.sh/hpm-enabled` annotation to the template metadata, which syncs
        automatically to the cluster on creation. It also sets
        `enabled: true` and `central: true` under the [controlPlane.hostPathMapper](/docs/vcluster/next/configure/control-plane/components/host-path-mapper) field in the vcluster.yaml.
      </Step>
      <Step>
        Finish configuring anything else on your cluster,
        then click 
        <Button>Create Cluster</Button>.
      </Step>
    </Flow>
  </TabItem>
  <TabItem value="existing">
    <Flow id="enable-central-hpm-virtualcluster-existing">
      <Step>
        From the project drop-down menu, click the project that contains the
        cluster where you want to enable Central HostPath Mapper.
      </Step>
      <Step>
        Hover over the cluster where you want to enable Central HostPath Mapper to reveal the <Label>Edit</Label> button.
        Click <Label>Edit</Label>.
      </Step>
      <Step>
        Go to the <Label>Advanced Control Plane</Label> section and find
        **Host Path Mapper**.
      </Step>
      <Step>
        Turn on <Label>Enable host path mapper</Label>. This adds the
        `loft.sh/hpm-enabled` annotation to the template metadata, which syncs
        automatically to the cluster on creation. It also sets
        `enabled: true` and `central: true` under the [controlPlane.hostPathMapper](/docs/vcluster/next/configure/control-plane/components/host-path-mapper) field in the vcluster.yaml.
      </Step>
      <Step>
        Finish configuring anything else on your cluster,
        then click <Button>Save Changes</Button>.
      </Step>
    </Flow>
  </TabItem>
</Tabs>
