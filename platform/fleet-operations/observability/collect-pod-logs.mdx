The `cluster-collector` template, described in [Configure edge collectors](./configure-edge-collectors.mdx), can also ship pod logs through the Write Gateway. Log
collection is off by default. When you set `collectLogs` to `"true"`, the `otel-daemon`
collector tails the log file of every pod on each node it runs on. It sends the records to
the gateway with the same `metrics-writer` token it uses for metrics.

The gateway stamps each log record with the same `vcluster_platform_*` resource attributes it
stamps on metrics, taken from the writer key's verified scope. The collector can't set or
override these attributes. See the [labels reference](./labels-reference.mdx).

:::warning Use log collection only on clusters with private nodes
The collector reads every pod log on the node, not only the pods of its own cluster, and
labels every record with its own cluster's identity. On shared nodes, it would collect
other tenants' logs and attribute them to this cluster. Platform doesn't block this, so only
set `collectLogs` for clusters that run on their own
[private nodes](/docs/vcluster/deploy/worker-nodes/private-nodes).
:::

## Turn on log collection

Log collection runs the `otel-daemon` collector as group `0` so it can read the node's pod
log files. The collectors skip their own logs.

1. Add a destination with `signal: logs` to the observability connector. The gateway only
   builds a logs pipeline when the connector has at least one logs destination. Without
   one, the gateway rejects incoming logs. The collectors record export errors and discard
   the records. See
   [Forward telemetry to additional destinations](./forward-telemetry.mdx).

1. Set `collectLogs` in the application's parameters:

   ```yaml title="fleet-edge-collectors.yaml"
   spec:
     parameters:
       destinationNamespace: observability
       collectLogs: "true"
   ```

1. Query your logs backend for records whose `vcluster_platform_instance` attribute names
   this cluster. If none arrive, see
   [Pod logs don't arrive](./troubleshooting.mdx#pod-logs-dont-arrive).
