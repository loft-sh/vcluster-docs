Getting capacity out of vMetal takes two choices. First, which driver provisions the server. Second, what that server becomes once it's provisioned.

## 1. Choose a provisioning driver

Start with the workflow that matches the infrastructure you provide. Each driver uses the same `NodeClaim` provisioning API and lifecycle.

| If you want to | Start with |
|---|---|
| Provision a bare metal Machine | [Configure the Metal3 driver](./drivers/bare-metal/metal3/overview.mdx#get-started) |
| Provision a virtual Machine | [Configure the KubeVirt driver](./drivers/virtual-machines/kubevirt.mdx#example-vcluster-with-static-kubevirt-node) |
| Use existing BCM-managed infrastructure | [Configure the BCM driver](./drivers/bare-metal/bcm.mdx) |
| Provision through Terraform or OpenTofu | [Configure the Terraform driver](./drivers/virtual-machines/terraform.mdx) |

The infrastructure operator configures the driver and makes capacity available. Platform and Tenant administrators define which resources Projects can consume.

## 2. Choose what the server becomes

Once servers are registered and a node type describes them, decide what to claim them for. All three paths create a `NodeClaim` and draw from the same pool. They differ by a field or two on the request.

| If you want to | Go to |
|---|---|
| Hand out a server over SSH, with no Kubernetes on it | [Independently provisioned machines](./deploy/independently-provisioned-machines.mdx) |
| Run a tenant cluster's control plane on your own hardware | [Control plane machines](./deploy/control-plane-machines.mdx) |
| Give an existing tenant cluster dedicated worker capacity | [Tenant cluster nodes](./deploy/tenant-cluster-nodes.mdx) |
