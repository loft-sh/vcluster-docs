Start with the workflow that matches the infrastructure you provide. Each driver uses the vMetal Machine API and lifecycle.

| If you want to | Start with |
|---|---|
| Provision a bare metal Machine | [Configure the Metal3 driver](./drivers/bare-metal/metal3/overview.mdx#get-started) |
| Provision a virtual Machine | [Configure the KubeVirt driver](./drivers/virtual-machines/kubevirt.mdx#example-vcluster-with-static-kubevirt-node) |
| Understand how a Machine becomes a private node | [Attach Machines to tenant clusters](./concepts/cluster-attachment.mdx) |
| Configure reusable images, SSH keys, and Machine configuration | [Images and reusable configuration](./images/os-images.mdx) |

The infrastructure operator configures the driver and makes capacity available. Platform and Tenant administrators define which resources Projects can consume. A Project user then requests that capacity from a tenant cluster through [Private Nodes](/docs/vcluster/deploy/worker-nodes/private-nodes/) or [Auto Nodes](/docs/vcluster/deploy/worker-nodes/private-nodes/auto-nodes/).
