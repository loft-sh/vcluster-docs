A `NetworkEnvironment` describes the network that machines join when a driver provisions them.
It is cluster scoped, so it is not tied to a single project or namespace.
Each environment names one driver in `spec.providerRef` and carries that driver's settings in `spec.properties`.

Drivers use environments differently.
Some provision real infrastructure from one, such as a VPC and an address range.
Others manage their own site networking and never read an environment at all.
See the [NICo driver guide](../drivers/bare-metal/nico.mdx#create-a-network) for a driver that requires one.

## Decide who a network belongs to

Every environment records who it is for.
An operator creates the environment and states the assignment as a label:

| Label | Value | Meaning |
| --- | --- | --- |
| `tenant.vcluster.com/exclusive-to` | a Tenant name | An operator lends this environment to that Tenant. |
| `tenant.vcluster.com/exclusive-to` | empty string | The environment is reserved for the platform. |
| `tenant.vcluster.com/owner` | a Tenant name | A Tenant created this environment for itself. |

The platform assignment is an empty value rather than a name, because the platform has no Tenant name of its own.
The label must still be present.
Its presence, not its value, is what records an assignment, so an environment with no label at all is unassigned rather than platform owned.

Do not set both labels.
An environment is either lent to a Tenant by an operator or owned by a Tenant, never both.

The API requires an assignment when you create the environment:

```text
network environment must be assigned to a tenant or the platform
```

When you create an environment as a Tenant administrator, omit the label.
The API records Tenant ownership for you.
Tenant-scoped reads hide these labels, so an absent label in that view does not mean the environment is unassigned.

## What you cannot change later

Once an environment carries an assignment, both the assignment and the whole `spec` are immutable:

```text
tenant assignment cannot be changed or removed
spec cannot be changed after assignment to a tenant
```

This includes `providerRef` and every driver property.
To change any of it, create a replacement environment and move its workloads across.
Decide the assignment and the network settings before you apply the manifest.

## How a machine selects a network

A `NodeClaim` reaches an environment in one of two ways:

- It names one explicitly, through the network environment property or `spec.environmentRef`.
- It names none, and the driver's default applies.
  Mark that default with the `machines.vcluster.com/is-default-environment` annotation on the environment.

A project restricts which environments its claims may use.
A claim that names an environment its project excludes fails with `network environment is not allowed in project`.

The environment's `providerRef` must match the provider of the workload that uses it.

## Check that an environment is ready

A driver that provisions infrastructure reports progress on the environment.
Wait for the `Ready` condition before you create machines against it:

```bash
kubectl get networkenvironment <name> -o yaml
kubectl wait networkenvironment/<name> --for=condition=Ready --timeout=10m
```
