A `NetworkEnvironment` describes the network that machines join when a driver provisions them.
It is cluster scoped, so it isn't tied to a single project or namespace.
Projects, clusters, and standalone machines share environments, and each project can [narrow which ones it allows](../../tenants/projects/allowed/network-environments.mdx).
The platform doesn't create environments automatically. A platform administrator creates each one and assigns it.
Each environment names one driver in `spec.providerRef` and carries that driver's settings in `spec.properties`.
The provider is required when you create an environment, and only that provider's node claims can use it.

Drivers use environments differently.
Some provision real infrastructure from one, such as a VPC and an address range.
Others don't require one and provision nothing from it, though they can still read its properties.
See the [NICo driver guide](../drivers/bare-metal/nico.mdx#create-a-network) for a driver that requires one.

## Decide who a network belongs to

Every environment records who it's for.
A platform administrator creates the environment and states the assignment with a label:

| Label | Value | Meaning |
| --- | --- | --- |
| `tenant.vcluster.com/exclusive-to` | a Tenant name | The operator lends this environment to that Tenant. |
| Neither label | | The environment belongs to the platform. |
| `tenant.vcluster.com/owner` | a Tenant name | A Tenant created this environment on an earlier release. Tenants can't create environments now. Don't set this label yourself. |

The `exclusive-to` label must name a Tenant. The API refuses an empty value, so leave the label off to keep an environment for the platform.

Tenants can't create environments. The API refuses a create from a Tenant session:

```text
network environments are created by platform admins and assigned to tenants
```

Tenant-scoped reads hide these labels, so an absent label in that view doesn't mean the environment belongs to the platform.

## What you can't change later

After you create an environment, its assignment, `providerRef`, and driver properties can't change.
The API refuses the update with errors like these:

```text
tenant assignment cannot be changed after creation; delete and recreate the network environment to assign it differently
providerRef cannot be changed
properties cannot be changed after creation
```

You can still edit the display name, the owner and access settings, and metadata, such as the default annotation.
To change anything else, create a replacement environment and move its workloads across.
Decide the assignment and the network settings before you create the environment.

This manifest creates an environment for the platform and makes it the default for its provider. It carries no assignment label:

```yaml
apiVersion: management.loft.sh/v1
kind: NetworkEnvironment
metadata:
  name: platform-network
  annotations:
    machines.vcluster.com/is-default-environment: "true"
spec:
  displayName: Platform network
  providerRef: my-provider
  properties: {}
```

Replace `my-provider` with your NodeProvider's name and add the driver's properties.

Every authenticated user can list environments, but the list only shows the ones they can access.
A Tenant's users see only environments that Tenant owns or has been assigned.

## How a machine selects a network

A NodeClaim reaches an environment in one of two ways:

- It names one explicitly, through the network environment property or `spec.environmentRef`.
- It names none, and the provider's default applies.
  Mark that default by setting the `machines.vcluster.com/is-default-environment` annotation on the environment to `"true"`.
  Only environments whose `providerRef` matches the claim's provider are candidates, and each provider can have only one default.
  Marking a second default doesn't unmark the first. While two are marked, every claim that relies on the default fails with `multiple default network environments found for node provider`.

The claim resolves environments within its project's scope.
A Tenant project only finds environments assigned to or owned by that Tenant, and a platform project finds platform environments.
When the named environment is out of scope, the claim waits rather than failing.

A project can also restrict which environments its claims use.
A claim that names an environment its project excludes fails with `network environment is not allowed in project`.
See [allowed network environments](../../tenants/projects/allowed/network-environments.mdx).

Standalone control plane nodes created through Auto Nodes copy the properties of the first `privateNodes.autoNodes` entry that uses the same provider.
They land in the same environment as that entry's worker nodes. Without a matching entry, the provider's default applies.

An environment serves only its own provider's node claims.
A project is offered only environments whose provider one of its allowed node types names, or whose provider owns a Machine assigned to the project's Tenant.
A claim that names another provider's environment is refused when it's created:

```text
network environment "<name>" belongs to node provider "<provider>", not "<claim provider>"
```

Creating an environment without a `providerRef` fails with `network environment must reference a node provider`.
Naming a NodeProvider that doesn't exist fails with `node provider "<name>" does not exist`.
Environments created without a provider on an earlier release still exist.
New node claims can't use them, and you can't add a provider later, so replace them.

## Check that an environment is ready

Every environment reports a `Ready` condition, summarizing whether its driver has provisioned and synced the infrastructure.
Wait for `Ready` before you create machines against it:

```bash
kubectl get networkenvironments.management.loft.sh <name> -o yaml
kubectl wait networkenvironments.management.loft.sh/<name> --for=condition=Ready --timeout=10m
```

## Delete an environment

Deleting an environment waits until no node claim uses it.
Until then it stays terminating, and its status reports the reason `NodeClaimsBound` with the names of the claims that hold it.
The driver then removes the infrastructure it provisioned for the environment.
Delete the clusters and instances that use an environment before you delete it.
