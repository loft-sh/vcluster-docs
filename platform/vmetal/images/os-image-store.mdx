An OS image store is the bucket that holds the OS images you upload to the platform. You connect it with an OS Image Store connector, and an [OS image](./os-images.mdx) names that connector to store its file.

Upload bytes never pass through the platform. The platform signs short-lived URLs, and the browser or the CLI sends the image straight to the bucket.

The image store works with AWS S3 and with S3-compatible stores such as MinIO or SeaweedFS.

## Grant the permissions

The access key that the connector uses needs these permissions on the objects in the bucket:

| Permission | Used for |
|---|---|
| `s3:PutObject` | Starting an upload, uploading its parts, and completing it. |
| `s3:ListMultipartUploadParts` | Checking that the upload session is still open on every `upload` call after the first, and that every part arrived before completing an upload. |
| `s3:AbortMultipartUpload` | Dropping an upload that wasn't finished. |
| `s3:GetObject` | Reading an image's size and downloading it during provisioning. |
| `s3:DeleteObject` | Removing an image's file when the OS image is deleted. |
| `s3:ListBucket` | Optional. Lets the store test report a bucket that doesn't exist. |

A policy for AWS S3:

<InterpolatedCodeBlock
  title="os-image-store-policy.json"
  language="json"
  code={'{\n  "Version": "2012-10-17",\n  "Statement": [\n    {\n      "Effect": "Allow",\n      "Action": [\n        "s3:PutObject",\n        "s3:ListMultipartUploadParts",\n        "s3:AbortMultipartUpload",\n        "s3:GetObject",\n        "s3:DeleteObject"\n      ],\n      "Resource": "arn:aws:s3:::[[GLOBAL:BUCKET]]/*"\n    },\n    {\n      "Effect": "Allow",\n      "Action": "s3:ListBucket",\n      "Resource": "arn:aws:s3:::[[GLOBAL:BUCKET]]"\n    }\n  ]\n}'}
/>

## Allow browser uploads

A browser upload sends `PUT` requests to the bucket from the platform's web address, so the bucket needs a CORS rule that allows that origin. Uploads from the CLI don't need one.

Set the origin to the address you open the platform UI with:

<InterpolatedCodeBlock
  title="os-image-store-cors.json"
  language="json"
  code={'{\n  "CORSRules": [\n    {\n      "AllowedOrigins": ["[[GLOBAL:PLATFORM_URL]]"],\n      "AllowedMethods": ["PUT"],\n      "AllowedHeaders": ["*"]\n    }\n  ]\n}'}
/>

Apply it to an AWS S3 bucket:

<InterpolatedCodeBlock
  language="bash"
  code={'aws s3api put-bucket-cors --bucket [[GLOBAL:BUCKET]] --cors-configuration file://os-image-store-cors.json'}
/>

If the UI reaches the platform under more than one address, list each one in `AllowedOrigins`.

## Create the connector

<InterpolatedCodeBlock
  title="os-image-store.yaml"
  language="yaml"
  code={'apiVersion: management.loft.sh/v1\nkind: Connector\nmetadata:\n  name: os-images\nspec:\n  displayName: OS images\n  imageStore:\n    protocol: s3\n    s3:\n      # Leave the endpoint empty for AWS S3. Set it for a self-hosted store.\n      endpoint: ""\n      bucket: [[GLOBAL:BUCKET]]\n      region: [[GLOBAL:REGION]]\n      # Most self-hosted stores need path-style addressing.\n      forcePathStyle: false\n      accessKey: [[VAR:ACCESS_KEY:AKIAEXAMPLE]]\n      secretKey: [[VAR:SECRET_KEY:<secret-key>]]'}
/>

:::warning
The manifest holds the secret key in plain text. Don't commit it to version control.
:::

```bash
kubectl apply -f os-image-store.yaml
```

| Field | Description |
|---|---|
| `s3.endpoint` | Address of the object store, starting with `http://` or `https://`. Leave it empty for AWS S3. |
| `s3.bucket` | Name of the bucket that holds the images, without a folder. A name that contains `/` fails with `InvalidStoreName`. |
| `s3.region` | Region of the bucket. Required for every store, because the request signature covers it. |
| `s3.forcePathStyle` | Address the bucket as a path (`https://endpoint/bucket`) instead of a host name. |
| `s3.accessKey`, `s3.secretKey` | Credentials of the key the platform signs with. |
| `s3.sessionToken` | Session token of temporary credentials. AWS keys that start with `ASIA` need it. |

Use long-lived credentials where possible. A signed upload URL stays valid for 24 hours, but only while the credentials that signed it are valid. Temporary credentials end every upload that outlasts them.

## Check the connection

Each time you save the connector, the platform tests the store. It starts an upload in the bucket under `.platform-probe/` and drops it right away. The result is the `StoreAccessible` condition on the connector. Saving never fails because of the test, so you can create the connector before the bucket is ready.

```bash
kubectl get connectors.management.loft.sh os-images -o jsonpath='{.status.conditions[?(@.type=="StoreAccessible")]}'
```

When the condition is `False`, its message names the setting to fix:

| Reason | Fix |
|---|---|
| `MissingSessionToken` | The access key is temporary (`ASIA`). Add its session token. |
| `UnknownAccessKey` | The store doesn't recognize the access key. Check the key and the endpoint. |
| `SecretKeyMismatch` | The secret key doesn't belong to the access key. |
| `CredentialsRejected` | The store rejected the credentials. Check the key pair and its permissions. |
| `AccessDenied` | The key may not write to the bucket. The bucket may belong to another account, or a policy denies access. |
| `WrongRegion` | The bucket is in another region. The message names the region to set. |
| `WrongEndpoint` | The bucket must be reached through another region or endpoint. |
| `StoreNotFound` | The bucket doesn't exist. |
| `InvalidStoreName` | The bucket name contains `/`. Set only the bucket name, without a folder. |
| `Refused` | The store refused the request for another reason, which the message names. |
| `Unreachable` | The store didn't answer. Check the endpoint and that the store is running. |

After you fix the store, save the connector again to repeat the test. The condition shows the result of the last store call, from a save, an upload, or a finalize. Credentials that expire later surface when an upload fails, with the same message.

The test doesn't check the CORS rule. A missing rule shows when a browser upload fails.
