Certified Stacks are tested [StackTemplates](../../../tenants/templates/what-are-stacks.mdx) and supporting resources bundled with vCluster Platform. They package multi-application integrations that need dependency ordering, health gates, and shared configuration.

Bundled StackTemplates carry the certified marker and are read-only in the Platform UI. They use the same StackTemplate and StackInstance APIs as custom Stacks.

## Understand the certified catalog

Platform 5.0 bundles NVIDIA Run:ai, NVIDIA Dynamo, and Saturn Cloud Enterprise as certified integrations. Together they contain six StackTemplates, three VirtualClusterTemplates, and the Apps those templates reference.

| Integration | Deployment models | Components |
| --- | --- | --- |
| [NVIDIA Run:ai](./runai.mdx) | Dedicated control plane and central control plane | vCluster, NVIDIA GPU components, and NVIDIA Run:ai 2.26 |
| [NVIDIA Dynamo](./nvidia-dynamo.mdx) | One runtime per cluster or control plane cluster | NVIDIA Dynamo operator, NATS, and etcd |
| [Saturn Cloud Enterprise](https://github.com/loft-sh/vcluster-stacks/blob/v1.0.0/certified-stacks/saturn/README.md) | One installation per cluster or control plane cluster | Saturn Cloud Helm operator, which installs the Saturn Cloud Enterprise components |

Each Platform release pins one release of the upstream [`vcluster-stacks` repository](https://github.com/loft-sh/vcluster-stacks). Platform 5.0 bundles `v1.0.0`. The repository's [`certified-stacks` directory](https://github.com/loft-sh/vcluster-stacks/tree/v1.0.0/certified-stacks) contains the source manifests, tests, and full implementation guide for each integration.

Platform records which revision of the bundle it applied. When an upgrade ships a newer revision, Platform applies the certified objects again and creates the ones that are new. Fields the bundle sets return to their bundled values, but fields you added that the bundle doesn't set are kept. Certified objects that a later bundle drops aren't deleted. Platform skips any certified object annotated with `loft.sh/skip-update: "true"`, which also means it stops receiving fixes.

## Use a certified stack

Choose a deployment model on the integration page. Then use the administrator guide to validate prerequisites and follow the supported lifecycle:

- [Choose an NVIDIA Run:ai model](./runai.mdx).
- [Install the NVIDIA Dynamo runtime](./nvidia-dynamo.mdx).
- [Install Saturn Cloud Enterprise](https://github.com/loft-sh/vcluster-stacks/blob/v1.0.0/certified-stacks/saturn/README.md). Its upstream guide covers registration, parameters, and requirements.
- [Manage Certified Stacks](../../../tenants/templates/certified-stacks.mdx).
- [Troubleshoot Stacks](../../../tenants/troubleshoot/stacks.mdx).

Certified Stack orchestration doesn't have a separate license feature. Each task uses the feature for the resource it creates. Every bundled template contains only App tasks, and [Apps](../../../tenants/templates/what-are-apps.mdx) are available on every plan. Platform installs the bundle only when the license includes the Apps feature. The bundled VirtualClusterTemplates also need a license feature for cluster management or for the security-hardened vCluster image.

## Customize a certified stack

Certified StackTemplates are read-only in the Platform UI. The management API doesn't block edits, but the next bundle revision resets every field the bundle sets. To change one, create your own StackTemplate from the certified stack's YAML. Give it a different name, and remove the `vcluster.com/certified` annotation. Your template is a separate resource and doesn't receive changes from later certified bundles.

Keep the bundled object unchanged so its source and support status remain clear. Review task dependencies, fixed names, chart versions, and output namespaces together when modifying your template.

For the steps, see [Customize a certified stack](../../../tenants/templates/certified-stacks.mdx#customize-a-certified-stack).

## Understand the previous workflow

Earlier Certified Stacks are repository-based reference implementations. They can include Terraform, Helm, and other orchestration outside the Stack API. Those implementations remain available on the [`certified-stacks-legacy` branch](https://github.com/loft-sh/vcluster-stacks/tree/certified-stacks-legacy) of the `vcluster-stacks` repository for users who rely on them.

The native bundle, introduced in Platform 4.12, is a separate delivery model. It seeds StackTemplates directly into Platform and lets users install StackInstances through the UI or management API.
