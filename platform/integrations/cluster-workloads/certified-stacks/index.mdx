Certified Stacks are first-party integrations built from tested [StackTemplates](../../../tenants/templates/what-are-stacks.mdx) and supporting resources bundled with vCluster Platform. They package multi-application integrations that need dependency ordering, health gates, and shared configuration.

Bundled StackTemplates carry the certified marker and are read-only. They use the same StackTemplate and StackInstance APIs as custom Stacks.

## Understand the certified catalog

Platform v5.0 includes NVIDIA Run:ai and NVIDIA Dynamo integrations in its Certified Stack catalog.
These integrations are included with Platform. You select a template and supply the parameters for your environment.
vCluster maintains the orchestration templates; NVIDIA develops the underlying applications.

| Integration | Deployment models | Components |
| --- | --- | --- |
| [NVIDIA Run:ai](./runai.mdx) | Dedicated control plane and central control plane | vCluster, NVIDIA GPU components, and NVIDIA Run:ai 2.26 |
| [NVIDIA Dynamo](https://www.vcluster.com/blog/nvidia-dynamo-with-vcluster) | Runtime in a cluster or on a connected control plane cluster | Distributed model-serving runtime |

The bundle is pinned in each Platform release. The upstream [vcluster-stacks repository](https://github.com/loft-sh/vcluster-stacks) contains its source manifests, tests, and exhaustive implementation guidance. The same repository also hosts Community Stacks from customers, partners, and the community. Platform doesn't bundle them.

## Use a certified stack

Choose a deployment model on the integration page. Then use the administrator guide to validate prerequisites and follow the supported lifecycle:

- [Choose an NVIDIA Run:ai model](./runai.mdx).
- [Manage Certified Stacks](../../../tenants/templates/certified-stacks.mdx).
- [Troubleshoot Stacks](../../../tenants/troubleshoot/stacks.mdx).

Certified Stack orchestration doesn't have a separate license feature. Each task uses the feature for the resource it creates. The bundled NVIDIA Run:ai templates contain App tasks, and [Apps](../../../tenants/templates/what-are-apps.mdx) are available on every plan.

## Customize a certified stack

Certified StackTemplates are read-only. To change one, create your own StackTemplate from the certified stack's YAML. Give it a different name, and remove the `vcluster.com/certified` annotation. Your template is a separate resource and doesn't receive changes from later certified bundles.

Keep the bundled object unchanged so its source and support status remain clear. Review task dependencies, fixed names, chart versions, and output namespaces together when modifying your template.

For the steps, see [Customize a certified stack](../../../tenants/templates/certified-stacks.mdx#customize-a-certified-stack).

## Understand the previous workflow

Earlier Certified Stacks are repository-based reference implementations. They can include Terraform, Helm, and other orchestration outside the Stack API. Those implementations remain available in the repository for users who rely on them.

The native Platform v4.12 bundle is a separate delivery model. It seeds StackTemplates directly into Platform and lets users install StackInstances through the UI or management API.
