A connector stores the connection settings that vCluster Platform uses to reach an external service. Platform features reference it by name. For example, a database connector lets Platform provision a separate backing database for each cluster.

Platform 5.0 adds the cluster-scoped `Connector` resource in `management.loft.sh/v1`. It serves the existing connector Secrets in the Platform namespace. Existing connectors become available through this API without copying credentials or changing their names.

## Choose a connector

Set exactly one payload section in `spec`. That section selects the connector type. There is no `spec.type` field, and you can't change the type after creation.

| Integration | Payload section | Backing Secret type label | License feature for API writes |
| --- | --- | --- | --- |
| [Database](./database.mdx) | `sharedDatabase` | `shared-database` | `connector-external-database` |
| [Argo CD and Akuity](../../gitops-cicd/argocd/connect-argocd.mdx) | `argoCd` | `argocd` | `argo-integration` |
| [Observability](./observability.mdx) | `observability` | `observability` | `fleet-observability` |
| [OS image storage](../../../vmetal/images/os-images.mdx) | `imageStore` | `os-image-store` | `machine-management` |
| [NetBox](./netbox.mdx) | `netBox` | `netbox` | `auto-nodes-metal3` |

Create and update require the corresponding license feature. Get, list, and delete remain available after a license expires, subject to access permissions.

## Manage and use connectors

Platform admins create connectors through the management API or write the backing Secrets directly. Both paths use the same stored configuration. The API provides validation, type-specific defaults on create, and status conditions.

Use a kubeconfig for the Platform management API when running commands against `connectors.management.loft.sh`. Use a kubeconfig for the Kubernetes cluster hosting Platform when managing the backing Secrets.

The API supports create, get, list, update, patch, and delete. Watch and collection deletion aren't supported. Poll lists when building automation.

Use server-side apply, imperative commands, or read-modify-write replacement. Client-side apply can't reliably track its previous configuration because the API withholds the last-applied annotation.

See [Manage connectors and tenant grants](./manage.mdx) for examples and [Connector API reference](../../../api/resources/connector.mdx) for fields and endpoints.

## Control access to configuration

Bind `loft-connectors-viewer` for get and list, or `loft-connectors-admin` for connector management. These roles aren't assigned by default. Project membership alone doesn't grant connector discovery.

A caller with update permission receives the full configuration, including credentials. Other callers receive a reduced view. Tenant sessions always receive the reduced view, even when their role grants update.

Every reduced view includes the name, display name, description, and a payload section identifying the type. It also includes these type-specific fields:

| Type | Additional configuration visible to viewers |
| --- | --- |
| Database | Database dialect |
| Argo CD | None |
| Observability | None |
| OS image store | Protocol (`s3`) |
| NetBox | URL and `insecure` setting |

Condition types, statuses, and reasons remain visible. Condition messages and most metadata describing management are removed. Empty connection fields in a reduced view don't mean the stored connector lacks credentials.

The default audit policies record connector requests at metadata level, without request or response bodies. Review custom audit policies separately.

## Preserve existing integrations

Direct Secret writers remain supported. They bypass API validation and must keep the documented Secret format valid. The API serves only recognized connector types in the Platform namespace.

An API replacement writes the fields it models. Send back metadata and other configuration that you want to retain. Unmodeled Secret data keys and withheld annotations don't survive replacement.

Credential preservation differs by type and authentication method. See [Update credentials](./manage.mdx#update-credentials) before changing a connector through automation.

The old list-only `DatabaseConnector` resource is deprecated in place. It remains available, and no removal is announced. See [Migrate database discovery](./manage.mdx#migrate-database-discovery).
