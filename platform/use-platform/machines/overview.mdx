An instance is a claim on a physical or virtual server managed by vCluster Platform through a node provider. The Platform API represents each instance with a `NodeClaim`. Instances abstract the provisioning details so platform administrators can offer self-service access to compute resources. Users request instances through cluster Auto Nodes or directly when they need standalone servers outside the cluster lifecycle.

:::note Assigning a Machine to a tenant
A platform admin can assign a [Machine](../../vmetal/concepts/machine-inventory.mdx), the inventory record of a server and not the instance that claims it, to one [tenant](../../understand/what-are-tenants.mdx)
exclusively, which takes it out of the shared pool. See
[Assign dedicated resources](../../administer/tenants/create-and-configure-tenants.mdx#assign-dedicated-resources).
:::

Each instance uses a [node provider](../../vmetal/concepts/machine-types-and-nodetypes.mdx) that handles the actual provisioning. A provider can create VMs, provision bare metal servers, or run Terraform scripts.
For KubeVirt-backed infrastructure, administrators can also manage KubeVirt VMs directly from the [Virtual Machines](../../vmetal/drivers/virtual-machines/overview.mdx) page.

## How instances are created

Instances are created in two ways:

- **Auto Nodes**: When a cluster uses [private nodes and Auto Nodes](/docs/vcluster/deploy/worker-nodes/private-nodes/auto-nodes/), the platform automatically creates scalable pools of instances. [Karpenter](/docs/vcluster/configure/vcluster-yaml/private-nodes/auto-nodes) decides when nodes are needed. The platform provisions them through the configured node provider. An instance can join the cluster as a worker or carry the cluster's control plane. See [Cluster nodes](../../vmetal/deploy/cluster-nodes.mdx) and [Control plane instances](../../vmetal/deploy/control-plane-machines.mdx).
- **Manual**: You can create an instance without connecting it to a cluster. This is useful for provisioning servers managed outside the cluster lifecycle. See [Independently provisioned instances](../../vmetal/deploy/independently-provisioned-machines.mdx).

In both cases, the node provider determines how the instance is provisioned. It selects the OS image, user data, and server configuration.

## Configuration

Instances inherit configuration from the node type used to provision them. This includes resource specifications, provider-specific properties, OS images, and SSH keys.

The following resources can be referenced by name in node type or `NodeClaim` properties to configure provisioning.

- [OS images](../../vmetal/images/os-images.mdx): Reusable image definitions containing the URL, checksum, and format for the operating system installed on the instance.
- [SSH keys](../../vmetal/images/ssh-keys.mdx): Public keys included in the instance's user data during provisioning.
