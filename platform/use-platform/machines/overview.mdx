A Machine is a provisioned server — physical or virtual — managed by vCluster Platform through a node provider. The Platform API represents each Machine request with a `NodeClaim`. Machines abstract the provisioning details so that platform administrators can offer self-service access to compute resources. Users request Machines either indirectly through cluster auto-nodes, or directly when they need standalone servers outside the cluster lifecycle.

Each Machine is backed by a [node provider](../../vmetal/concepts/machine-types-and-nodetypes.mdx) that handles the actual provisioning — creating VMs, provisioning bare metal servers, or running Terraform scripts.
For KubeVirt-backed infrastructure, administrators can also manage KubeVirt VMs directly from the [Virtual Machines](../../vmetal/drivers/virtual-machines/overview.mdx) page.

## How machines are created

Machines are created in two ways:

- **Auto nodes**: When a cluster is configured with [private nodes and auto nodes](/docs/vcluster/deploy/worker-nodes/private-nodes/auto-nodes/), the platform automatically creates scalable pools of Machines. [Karpenter](/docs/vcluster/configure/vcluster-yaml/private-nodes/auto-nodes) decides when nodes are needed, and the platform provisions them through the configured node provider. The Machine joins the cluster as a worker node. See [Cluster nodes](../../vmetal/deploy/cluster-nodes.mdx). A Machine can also carry a cluster's own control plane instead of joining one as a worker. See [Control plane machines](../../vmetal/deploy/control-plane-machines.mdx).
- **Manual**: Machines can also be created independently, without being connected to a cluster. This is useful for provisioning servers that are managed outside of the cluster lifecycle. See [Independently provisioned machines](../../vmetal/deploy/independently-provisioned-machines.mdx) for the walkthrough.

In both cases, the node provider determines how the Machine is provisioned — what OS image is installed, what user data is applied, and how the server is configured.

## Configuration

Machines inherit configuration from the node type they are provisioned from. This includes resource specifications, provider-specific properties, and provisioning settings like OS images and SSH keys.

The following resources can be referenced by name in node type or `NodeClaim` properties to configure provisioning.

- [OS images](../../vmetal/images/os-images.mdx): Reusable image definitions containing the URL, checksum, and format for the operating system installed on the Machine.
- [SSH keys](../../vmetal/images/ssh-keys.mdx): Public keys included in the Machine's user data during provisioning.
