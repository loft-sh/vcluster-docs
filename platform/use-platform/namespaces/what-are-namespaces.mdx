Namespaces are regular Kubernetes namespaces managed by vCluster Platform that are owned by a user or team.
In Kubernetes, namespaces provide a mechanism for isolating groups of resources within a single cluster.

In vCluster Platform, each namespace belongs to a Control Plane Cluster and project. Namespaces can be [created from a template](./create/create-with-template.mdx) to enforce isolation best practices or [created manually](./create/create-no-template.mdx) by project admins. Admins can [manage access](../../tenants/users-permissions/permissions/namespace.mdx) and users can [connect via CLI](./retrieve-kube-config.mdx).

:::info
For applications that require multiple namespaces or need to create cluster scoped resources, [clusters](/docs/vcluster/introduction/what-is-vcluster) are recommended instead.
:::

There are multiple key features you can use with namespaces:
- [Auto Sleep & Auto Delete](./key-features/sleep-mode.mdx) that puts namespaces to sleep when nobody is using them or delete namespaces that have been
idle for a while.
- [Isolation](./key-features/isolation.mdx) that applies ResourceQuotas, LimitRanges, and NetworkPolicies to a Namespace.
- [Prevent Deletion](./key-features/prevent-deletion.mdx) that prevents a Namespace from deletion.
- [Custom Links](./key-features/custom-links.mdx) that adds custom links to namespaces that point to external resources such as GitHub pull requests, Jira issues, or documentation.
