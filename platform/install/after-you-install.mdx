vCluster Platform is running. Use this checklist to take it from a fresh install to a platform your tenants can use. The items are usually done from top to bottom, but skip any that don't apply or that you finished during install. Each item links to the guide that owns the procedure.

- [ ] **Give the platform a domain.** Serve it at your own hostname with TLS, so users and agents reach a stable address. See [Custom domain](../administer/configure/installation-options/domain.mdx).
- [ ] **Set up sign-in.** Connect your identity provider so people sign in with the accounts they already have. See [SSO providers](../administer/authentication/single-sign-on.mdx).
- [ ] **Connect your clusters.** Connect each Kubernetes cluster where cluster control planes should run. See [Connect a cluster](../administer/control-plane-clusters/connect-cluster.mdx).
- [ ] **Add machines, if you run bare metal or VMs.** Connect a vMetal provisioning driver so the platform can provision private nodes and instances. See [Get started with vMetal](../vmetal/get-started.mdx).
- [ ] **Decide who can do what.** Create projects, and add users and teams with the roles they need. See [Create project](../tenants/projects/create.mdx) and [Users, teams, roles, and permissions](../tenants/users-permissions/overview.mdx).
- [ ] **Publish what tenants can create.** Create templates for the clusters, namespaces, and apps you offer. See [Create templates](../tenants/templates/create-templates.mdx).
- [ ] **Create your first cluster.** From a project, create a cluster from one of your templates to confirm that everything works end to end. See [Create a cluster from a template](../use-platform/clusters/create/create-with-template.mdx).
