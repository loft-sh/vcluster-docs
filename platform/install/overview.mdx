This section is for system admins installing vCluster Platform. The Kubernetes cluster you install it on becomes the control plane cluster. To configure and run the platform once it's installed, see [Administer the management plane](../administer/configure/introduction.mdx).

## Before you begin

Every install method needs the same starting point. Each method page lists the full prerequisites.

- **A Kubernetes cluster** where your current kube-context has admin access.
- **`kubectl` and Helm** on the machine you install from.
- **Egress to the license server** from the platform pods. If the cluster has no internet access, use an [air-gapped install](#install-in-a-specific-environment) instead.
- **Open network ports** between the platform and the clusters it connects to. See [Networking](../administer/control-plane-clusters/networking/overview.mdx).

## Choose an install method

All three methods install the same `vcluster-platform` Helm chart. They differ in how you manage the install afterward.

- **Get started quickly.** [With CLI](./quick-start-guide.mdx) installs the platform with one vCluster CLI command, opens the UI, and prompts you to create the admin user. It's the preferred method. You can export the configuration later if you move to GitOps.
- **Manage the install as a Helm release.** [With Helm](./helm.mdx) installs the chart directly, so you set the values yourself and can keep them in version control.
- **Manage the install with GitOps.** [With ArgoCD](./gitops.mdx) deploys the chart as an Argo CD Application. Argo CD must already run on the control plane cluster. The same approach works with other GitOps tools.

## Install in a specific environment

- **On a new managed cluster.** The [EKS](./environments/aws.mdx), [AKS](./environments/azure.mdx), and [GKE](./environments/gcp.mdx) guides create the cluster with the cloud provider's CLI, then install the platform with the vCluster CLI. Use them when you don't have a cluster yet.
- **Without internet access.** [With offline license key](./air-gapped/with-offline-license-key.mdx) mirrors the images and Helm charts into a private registry and licenses the platform offline. Use [With offline license server](./air-gapped/with-offline-license-server.mdx) instead when you need usage tracking and export from an in-cluster license service. [Platform database](./air-gapped/platform-database.mdx) explains the local database that stores usage snapshots for an offline license key.

## After you install

[After you install](./after-you-install.mdx) is a checklist that takes a fresh install to a platform your tenants can use. It covers the domain, sign-in, connected clusters, access, templates, and a first cluster.
