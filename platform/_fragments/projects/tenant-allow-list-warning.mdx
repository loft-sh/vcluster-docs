:::warning Project and tenant allow-lists follow different rules
Where the project belongs to a tenant, both layers apply and a project member only reaches
what both permit. The two layers write "everything" and "nothing" differently.

| Layer | Field | To allow everything | To allow nothing |
|-------|-------|---------------------|------------------|
| Project | <code>{props.field}</code>, a list of names | {props.unsetMeansAll ? "Leave the field unset" : <>Add an entry named <code>"*"</code>{props.perKind ? " for each template kind" : ""}</>} | {props.unsetMeansAll ? "Set an empty list" : "Leave the field unset or empty"} |
| Tenant | `allow.byLabels`, a label selector | Set an empty selector, which matches every admin-owned {props.resource} | Leave the selector unset. Assigned and shared instances still reach the tenant |

A label selector is a conjunction, so an empty one is vacuously true and matches every
admin-owned {props.resource}.{props.byName ? <> A tenant can also grant node types by name with <code>allow.byName</code>.</> : ""}

The tenant layer also needs its capability enabled. A disabled capability withholds every
{props.resource} from the tenant, including ones assigned to it. With the selector unset, the
tenant still reaches any {props.resource} a platform admin assigned to it or shared with every
tenant.

An allow-list set here has no effect on inventory the tenant was never granted. See
[Tenant boundary reference](../../tenants/manage-tenants/tenant-boundary-reference.mdx).
:::
