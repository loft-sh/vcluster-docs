:::warning Project and tenant allowlists follow different rules
In a tenant's project, a project member reaches only what both the project and
the tenant allow. The two layers write "everything" and "nothing" differently.

| Layer | Field | To allow everything | To allow nothing |
|-------|-------|---------------------|------------------|
| Project | <code>{props.field}</code>, a list of names | {props.unsetMeansAll ? "Leave the field unset" : <>Add an entry named <code>"*"</code>{props.perKind ? " for each template kind" : ""}</>} | {props.unsetMeansAll ? "Set an empty list" : "Leave the field unset or empty"} |
| Tenant | `allow.byLabels`, a label selector | Set an empty selector | Omit the selector |

An empty tenant selector matches every admin-owned {props.resource}. An omitted
selector grants none by label, but the tenant still reaches any {props.resource}
assigned to it or shared with every tenant.{props.byName ? <> The tenant layer can also grant node types by name with <code>allow.byName</code>.</> : ""}
The tenant capability must also be enabled. A disabled capability withholds
every {props.resource}, including ones assigned to the tenant.

A project allowlist can't add inventory the tenant was never granted. See
[Tenant boundary reference](../../tenants/manage-tenants/tenant-boundary-reference.mdx).
:::
