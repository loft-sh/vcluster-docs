This section is for the admins who run the platform itself, usually the system admin who installed it. The platform is the management plane. It runs on the control plane cluster, connects other control plane clusters through an agent, and reconciles what admins and users define into those clusters.

To understand how the pieces fit before you change them, see [Architecture](../overview/architecture.mdx) and [How Platform works](../overview/how-platform-works.mdx). To install the platform, see the [quick start guide](../install/quick-start-guide.mdx).

## Set up and secure

- **Configure the platform.** The [configuration introduction](./configure/introduction.mdx) explains the sections of the platform's `values.yaml`. [Installation options](./configure/installation-options/overview.mdx) control how the platform deploys, and [platform config](./configure/platform-configs/overview.mdx) controls how it behaves afterward.
- **Sign users in.** [SSO providers](./authentication/single-sign-on.mdx) connects an identity provider. Then [disable the local admin account](./authentication/disable-local-admin.mdx).
- **Authenticate tools and automation.** [Access keys](./authentication/access-keys.mdx) give the CLI and API clients credentials. [OIDC token exchange](./authentication/token-exchange.mdx) trades external tokens for access keys, and the platform can also act as an [OIDC provider](./authentication/oidc-provider.mdx).
- **Recover admin access.** [Reset the admin password](./authentication/reset-admin-password.mdx) when you're locked out of the platform.

## Connect control plane clusters

- **Understand connected clusters.** [What are connected clusters](./control-plane-clusters/what-are-clusters.mdx) explains the clusters where cluster control planes run.
- **Add one.** [Connect a cluster](./control-plane-clusters/connect-cluster.mdx) installs the agent on a cluster so the platform can manage it.
- **Configure the agent.** [Agent settings](./control-plane-clusters/agent-settings/overview.mdx) covers agent configuration, upgrades, security context, and least privilege mode.
- **Open the network.** [Networking](./control-plane-clusters/networking/overview.mdx) lists the ports and firewall rules, plus DERP relays, ingress suffixes, and regional endpoints.

## Run it reliably

- **Run more than one replica.** [High availability](./reliability-scaling/high-availability.mdx) runs the platform with multiple replicas.
- **Use an external database.** [Platform external database](./external-database/external-database.mdx) supports high availability deployments with multiple replicas.
- **Span regions.** [Multi-region platform](./reliability-scaling/multi-region/overview.mdx) runs the platform across AWS regions with DNS failover.
- **Know what fails when.** [Control plane outages](./reliability-scaling/control-plane-outages.mdx) explains what keeps working when the platform, a connected cluster, or a cluster control plane is down.
- **Back up and restore.** [Back up the platform](./backup-restore/backup-platform.mdx) and [restore it](./backup-restore/restore-platform.mdx), keeping the [license instance ID](./backup-restore/preserve-license.mdx) intact.

## Observe it

- **Logs.** [Logging](./logging/overview.mdx) explains the platform's audit, process, and workload logs. Audit logging itself is set up in [platform config](./configure/platform-configs/audit.mdx).
- **Metrics.** [Monitoring](./monitoring/overview.mdx) covers platform health metrics and workload metrics for a single cluster.
- **Notices.** The [Inbox](./inbox.mdx) collects product updates and license warnings for admins.

## Change it

- **Upgrade.** [Upgrade vCluster Platform](./upgrade-migrate/upgrade.mdx) with the CLI, Helm, or GitOps, matching how you installed it. Air-gapped installs follow [Upgrade in an air-gapped environment](./upgrade-migrate/upgrade-air-gapped.mdx).
- **Move it.** [Migrate the platform to a different cluster](./upgrade-migrate/migrate-to-hostcluster.mdx) moves it to a new control plane cluster.
- **Remove it.** [Uninstall](./uninstall.mdx) removes the platform with the vCluster CLI or Helm. It deletes every platform object, so back up anything you need first.

- [Troubleshooting](./troubleshoot/troubleshooting.mdx) covers common problems deploying and running the platform.

- [TSNet connection failures](./troubleshoot/tsnet-connectivity.mdx) covers clusters that never show as ready.
- [Platform database](./troubleshoot/platform-database.mdx) covers database problems in air-gapped installs.
- With an external database, see [Troubleshooting external database](./external-database/troubleshoot.mdx).
