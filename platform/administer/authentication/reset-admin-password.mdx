If you're locked out of vCluster Platform, choose a recovery method based on whether the admin account exists.

Use [Helm recovery](#recover-through-helm) to create a missing account or rotate an existing account's password without a platform login.
For installations with an external database, use this method rather than the CLI or kubectl password-reset procedures below.

If you still have UI access, use [Reset a user's password](../users-permissions/managing-users/reset-password.mdx) instead. It works for the admin account too.

:::note No authentication methods on the login page
If you don't see any authentication methods on the login page at all, password login was likely disabled and you lost access to SSO. Re-enable password login first, then come back to reset the password. See [Recovery](../../how-to/disable-local-admin.mdx#recovery).
:::

## vCluster CLI

If you are still authenticated using the vCluster CLI you can easily reset the admin password:

```bash
vcluster platform reset password --user=admin
```

:::warning Existing sessions and access keys are invalidated
Resetting a password through the CLI deletes all of that user's existing access keys, including browser sessions, other CLI sessions, and any API tokens the user generated. Anyone using the old password or an existing access key for this user must log in again. This does not apply to [Helm recovery](#recover-through-helm) or the [Kubectl](#kubectl) method below, which patches the password secret directly and leaves existing sessions and access keys untouched.
:::

## Kubectl

If you don't have CLI access, you can reset the password by patching the underlying Kubernetes secret directly.

### Find the password secret

Run the following command to look up the admin user's password reference:

```
$ kubectl get user admin -o yaml
apiVersion: management.loft.sh/v1
kind: User
metadata:
  ...
spec:
  passwordRef:
    key: password
    secretName: loft-user-secret-admin
    secretNamespace: vcluster-platform
...
```

Note the `secretName` and `secretNamespace` under `passwordRef`. Older installs may use the `loft` namespace instead of `vcluster-platform`. You'll use both values in the next step.

### Set a new password

Replace `SECRET_NAME`, `SECRET_NAMESPACE`, and `my-new-password` below with the values from the previous step and your new password, then run:

```bash
SECRET_NAME=loft-user-secret-admin
SECRET_NAMESPACE=vcluster-platform
NEW_PASSWORD_HASH=$(echo -n "my-new-password" | sha256sum | awk '{print $1}')

kubectl get secret "$SECRET_NAME" -n "$SECRET_NAMESPACE" -o json \
  | jq --arg password "$(printf '%s' "$NEW_PASSWORD_HASH" | base64)" '.data["password"]=$password' \
  | kubectl apply -f -
```

After that you should be able to log in to vCluster Platform with the user `admin` and your new password.

## Recover through Helm

Operators with access to the platform's Helm release and Kubernetes namespace can
recover access without a platform login. Use this procedure when:

- The admin never existed because the installation used `admin.create: false`.
- The admin User was deleted.
- An existing admin needs a new password on an external-database installation, or you want to rotate it through Helm configuration.

Recovery supports normal installations and installations with an external database, even with `env.DISABLE_DEFAULTS: "true"`.
It runs when a platform instance becomes leader.

Set `admin.create: true` and a password in the complete values file for your release.
Set a strong password with `admin.password`, or use an existing Kubernetes Secret
in the release namespace:

```yaml
admin:
  create: true
  passwordSecretRef:
    name: platform-admin-password
    key: password
```

The Secret key contains the plaintext password. `admin.passwordSecretRef` takes
precedence over `admin.password`. Password authentication must be enabled;
SSO-only installations can set `config.auth.password.disabled: false` in Helm values.

If you already use [environment-based Secret references](../../configure/platform-configs/overview.mdx#using-secret-references), that pattern also works:

```yaml
admin:
  create: true
  passwordSecretRef:
    name: ""
  password: "$PLATFORM_ADMIN_PASSWORD"
envValueFrom:
  PLATFORM_ADMIN_PASSWORD:
    secretKeyRef:
      name: platform-admin-password
      key: password
```

To rotate the password, update the selected Secret's `password` key, then apply the values and restart as shown below.

    'kubectl --namespace [[VAR:NAMESPACE:vcluster-platform]] rollout restart deployment/[[VAR:DEPLOYMENT:vcluster-platform]]\n' +
    'kubectl --namespace [[VAR:NAMESPACE:vcluster-platform]] rollout status deployment/[[VAR:DEPLOYMENT:vcluster-platform]]'}
/>

Select a chart version that includes admin recovery and use your complete values file. Replace the release,
namespace, and Deployment names with your installation's values. The explicit restart is
needed if the upgrade leaves the pod template unchanged, including when only the
source Secret's contents change. Allow leader handover to finish before testing login.
Recovery through Helm preserves existing sessions and access keys.

:::note Existing accounts
The first recovery run may preserve the existing password. If your configured password does not work, configure a different password and restart again.

Recovery does not unlock disabled accounts. See [SSO recovery](../../how-to/disable-local-admin.mdx#recovery).
:::

If recovery fails, check the platform startup logs for invalid password configuration or a credential Secret protected by `loft.sh/skip-update: "true"`.
