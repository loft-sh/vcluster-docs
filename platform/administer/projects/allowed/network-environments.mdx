Allowed network environments control which [network environments](../../../vmetal/concepts/network-environments.mdx) the NodeClaims in a project can use.
Network environments are shared across projects, so use this to keep a project on a subset of the networks its Tenant can reach.

The allowlist narrows what the project can already see. A Tenant project only reaches environments assigned to or owned by its Tenant, whatever the allowlist contains.

## Behavior

The project field is `spec.allowedNetworkEnvironments`. Each entry has a `name` that is the exact name of a network environment.

| Value | Effect |
|-------|--------|
| Unset (field omitted) | All accessible network environments are allowed. This is the default. |
| Empty list (`allowedNetworkEnvironments: []`) | No network environments are allowed. |
| One or more entries | Only the listed network environments are allowed. |

Matching rules:

- Names are case sensitive.
- Wildcards aren't supported. Network environment names can't contain dots, so the `provider.*` form used for [node types](./node-types.mdx) never matches.
- The platform rejects a NodeClaim at creation time if it explicitly names a disallowed environment.
- A NodeClaim that names no environment falls back to its provider's default. Defaults the allowlist excludes are skipped.

:::warning Removing an environment affects running claims
The platform checks the allowlist again for existing NodeClaims, not only new ones.
If you remove an environment that claims already use, those claims fail with the reason `NetworkEnvironmentNotAllowed`. Their nodes keep running, but the platform stops reconciling those claims.
Move workloads to an allowed environment before you narrow the list.
:::

Changing `allowedNetworkEnvironments` requires `update` permission on the project's `spec.allowedNetworkEnvironments` or `spec.*` subresource.

## Configure allowed network environments

<Tabs>
<TabItem value="ui" label="UI" default>

<Flow>
<Step>
Select the project in the project selector, then click <NavStep>Project Config</NavStep>.
</Step>
<Step>
In the <Label>Network Environments</Label> section, select <Label>Allow only specific network environments</Label>.
</Step>
<Step>
Add each environment the project can use.
</Step>
<Step>
Click <Button>Save changes</Button>.
</Step>
</Flow>

To lift the restriction, select <Label>Allow all network environments</Label>.

</TabItem>
<TabItem value="yaml" label="YAML">

Edit the project and set `spec.allowedNetworkEnvironments`:

```yaml
apiVersion: management.loft.sh/v1
kind: Project
metadata:
  name: team-a
spec:
  allowedNetworkEnvironments:
    - name: team-a-network
    - name: shared-gpu-network
```

This project can use only the `team-a-network` and `shared-gpu-network` environments.

To disallow all network environments in a project:

```yaml
spec:
  allowedNetworkEnvironments: []
```

</TabItem>
