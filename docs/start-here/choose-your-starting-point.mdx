A complete offering stacks four layers. Machines run a Kubernetes cluster. That cluster runs vCluster Platform and becomes the control plane cluster. Platform then delivers clusters and other services to your tenants.

You don't have to build every layer. Start at the first layer you don't already have, and reuse what you run today.

Building for your own engineering teams rather than for customers? The same layers apply, and your tenants are your internal teams. See [Internal platforms and dev clusters](../services/internal-platforms-and-dev-clusters.mdx) for that path.

## Servers only

Use one server to bootstrap the control plane cluster, then bring the rest of your servers in through vMetal.

1. **Install vCluster Standalone** on one Linux server. Standalone is a complete Kubernetes distribution that runs as a single binary, with no existing cluster required. See the [Standalone quick start](/docs/vcluster/next/quick-start/standalone).
2. **Install vCluster Platform** on that cluster with Helm, as a separate step. See [Install with Helm](/docs/platform/next/install/helm).
3. **Connect the rest of your servers** through a vMetal provisioning driver, such as Metal3 for servers you provision directly. See [Get started with vMetal](/docs/platform/next/vmetal/get-started).

## A provisioner or machine inventory

If you already manage servers or VMs with another system, vMetal can provision through it instead of replacing it.

1. **Install vCluster Platform** on any Kubernetes cluster. That cluster becomes the control plane cluster. See the [Platform quick start](/docs/platform/next/install/quick-start-guide).
2. **Create a node provider for the system you run.** vMetal supports these provisioning drivers:
   - [Metal3](/docs/platform/next/vmetal/drivers/bare-metal/metal3/overview), for bare metal servers you provision directly
   - NVIDIA Infra Controller (NICo), for servers already managed at a NICo site
   - [NVIDIA Base Command Manager](/docs/platform/next/vmetal/drivers/bare-metal/bcm), for servers managed in BCM
   - [KubeVirt](/docs/platform/next/vmetal/drivers/virtual-machines/kubevirt), for VMs on a KubeVirt cluster you operate
   - [Terraform](/docs/platform/next/vmetal/drivers/virtual-machines/terraform), for cloud VMs and anything else a Terraform provider can create
3. **Choose what the machines become.** A machine can be a [cluster node](/docs/platform/next/vmetal/deploy/cluster-nodes), host a [cluster control plane](/docs/platform/next/vmetal/deploy/control-plane-machines), or stay an [instance with no cluster](/docs/platform/next/vmetal/deploy/independently-provisioned-machines) that a tenant reaches over SSH. BCM supplies cluster nodes only, because it always joins the machine to a cluster.

## Kubernetes clusters

If you already run Kubernetes, install Platform on one of your clusters and connect the others.

1. **Install vCluster Platform** on one cluster, with the CLI or with Helm. That cluster becomes the first control plane cluster. See the [Platform quick start](/docs/platform/next/install/quick-start-guide).
2. **Connect your other clusters** as additional control plane clusters with `vcluster platform add cluster`. See [Connect a cluster](/docs/platform/next/administer/control-plane-clusters/connect-cluster).
3. **Give tenant workloads private nodes.** Join machines to each cluster as [private nodes](/docs/vcluster/next/deploy/worker-nodes/private-nodes) yourself, or let [Auto Nodes](/docs/vcluster/next/deploy/worker-nodes/private-nodes/auto-nodes) provision them on demand. See [Capacity models](../plan/capacity-models.mdx).

## Clusters created with vCluster

If you already run clusters with the vCluster CLI or Helm chart, bring them under Platform management instead of re-creating them.

1. **Install vCluster Platform** if you haven't yet. See the [Platform quick start](/docs/platform/next/install/quick-start-guide).
2. **Import each cluster** with `vcluster platform add vcluster`. Add `--all` to import the clusters in every namespace of the control plane cluster. For a Standalone cluster, use `vcluster platform add standalone` instead. See [Add existing clusters](/docs/platform/next/clusters/add-virtual-clusters).
3. **Decide how much Platform manages.** By default, an imported cluster stays externally managed instead of being managed by the platform agent. To have the agent manage it, connect its control plane cluster first, then import with `--external=false`. See [Platform-managed and externally deployed clusters](/docs/platform/next/clusters/externally-vs-platform-deployed).
