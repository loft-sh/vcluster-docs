Run a managed Kubernetes service on your GPU infrastructure. Each customer gets an isolated <GlossaryTerm term="tenant-cluster">tenant cluster</GlossaryTerm> with dedicated GPU nodes. Your product is what customers interact with. Platform is the operations layer your team runs behind it.

**Customer access model:** External paying customers, no direct Platform access. **Worker-node model:** Private nodes per customer. See [Choose a worker node model](../plan/choose-worker-node-model.mdx).

**Typical stack:** Standalone (HA) as the <GlossaryTerm term="control-plane-cluster">control plane cluster</GlossaryTerm>. Private nodes per customer cluster. vMetal for bare metal GPU lifecycle. vNode for workload runtime isolation.

**What makes this path different:** Customers never access Platform directly. They interact with your product. Platform RBAC locks direct access to your platform engineering team. This architecture also maps to the cluster-level isolation criteria that AI cloud buyers evaluate in frameworks like [ClusterMAX](https://www.vcluster.com/clustermax).

If your customers buy managed model endpoints instead of Kubernetes clusters, start with [Inference provider](./inference-provider.mdx). That path uses the same GPU infrastructure building blocks, but the customer-facing product boundary is an inference API and endpoint lifecycle instead of a tenant Kubernetes API.

## Day 0: Design decisions

| Decision | Read next | Outcome |
| --- | --- | --- |
| Choose the control plane deployment model | [Standalone deployment](/docs/vcluster/deploy/control-plane/binary/basics), [Architecture](/docs/vcluster/introduction/architecture) | Control planes as pods on an existing Kubernetes cluster, or Standalone on dedicated CPU nodes. Standalone is the common choice when no prior Kubernetes substrate exists. |
| Plan bare metal GPU provisioning | [vMetal docs](https://www.vmetal.ai/docs/), [Metal3 node provider](/docs/platform/next/vmetal/drivers/bare-metal/metal3/overview), [bare metal lifecycle](/docs/platform/next/vmetal/drivers/bare-metal/metal3/server-lifecycle) | Decide whether vMetal manages the full machine lifecycle (PXE, OS imaging, BMC, reclaim) or nodes are joined manually or using another provisioner. |
| Define per-customer node isolation | [Private Nodes](/docs/vcluster/deploy/worker-nodes/private-nodes), [node requirements](/docs/vcluster/deploy/worker-nodes/private-nodes/node-requirements) | Each customer's cluster gets its own dedicated GPU node pool with a separate CNI/CSI, eliminating interference between customers. |
| Plan network isolation | [VPN](/docs/vcluster/deploy/worker-nodes/private-nodes/vpn), [Netris integration](/docs/vcluster/deploy/control-plane/kubernetes-pod/environment/bare-metal) | Clusters connect to their private nodes over an encrypted VPN tunnel. Netris integration adds switch-level VLAN/VXLAN isolation per tenant. |
| Define the default network policy posture | [Network policy](/docs/vcluster/configure/vcluster-yaml/policies/network-policy) | Set a default-deny east-west posture per tenant template and confirm the control plane cluster's CNI enforces it. Some CNIs accept NetworkPolicy objects without enforcing them. |
| Choose runtime isolation model | [vNode docs](https://www.vnode.com/docs/), [Virtual Nodes](/docs/vcluster/introduction/architecture#virtual-nodes) | vNode provides kernel-level container isolation without VM overhead. Recommended when customers run privileged workloads, dynamic code execution, or need GPU access using CDI. |
| Choose the GPU scheduling model | [DeviceClasses](/docs/vcluster/configure/vcluster-yaml/sync/from-host/device-classes), [DRA ResourceClaims](/docs/vcluster/configure/vcluster-yaml/sync/to-host/DRA/resourceclaims) | Device-plugin-style `DeviceClass` sync covers simple, whole-GPU allocation. DRA `ResourceClaim` sync (Pro) supports fine-grained and shared GPU allocation. |
| Plan tenant storage | [Storage classes from host](/docs/vcluster/configure/vcluster-yaml/sync/from-host/storage-classes), [CSI storage capacities](/docs/vcluster/configure/vcluster-yaml/sync/from-host/csi-storage-capacities) | Decide which storage classes each tenant tier can request (etcd/control-plane storage vs. model weights and checkpoints), and whether to sync host `CSIStorageCapacity` for scheduler-aware placement. |
| Define cluster templates and AI stacks | [Templates](/docs/platform/next/tenants/templates/overview), [Stacks](/docs/platform/next/tenants/templates/what-are-stacks), [create a Stack template](/docs/platform/next/tenants/templates/create-stack-templates), [Certified Stacks](/docs/platform/next/integrations/cluster-workloads/certified-stacks) | Standardize each customer cluster and its AI software. Platform 4.12 includes Certified StackTemplates for dedicated and central NVIDIA Run:ai deployment models; create your own StackTemplates for other schedulers or developer environments. |
| Decide whether to sell inference endpoints | [Inference Provider](./inference-provider.mdx), [Inference serving stacks](/docs/vcluster/integrations/model-serving) | If your product abstracts Kubernetes away and exposes model endpoints, use the inference provider path for endpoint templates, serving stack deployment, routing, and autoscaling. |
| Plan the customer-facing provisioning API | [Product control plane on the Platform API](/docs/platform/next/integrations/api-workflows/product-control-plane), [Projects](/docs/platform/next/tenants/projects/create), [Quotas](/docs/platform/next/tenants/projects/quotas) | Your product API calls Platform to provision clusters. Define the project structure, quota model, and automation hooks that back your customer-facing workflows. |
| Plan durability | [Backing store](/docs/vcluster/configure/vcluster-yaml/control-plane/components/backing-store), [container control plane HA](/docs/vcluster/deploy/control-plane/kubernetes-pod/high-availability), [Standalone HA](/docs/vcluster/deploy/control-plane/binary/high-availability), [Platform HA](/docs/platform/next/administer/reliability-scaling/high-availability) | Choose the data store and replica model for Platform and per-customer control planes. |
| Plan security hardening and audit logging | [Security baseline](/docs/vcluster/security), [CIS hardening guide](/docs/vcluster/deploy/control-plane/kubernetes-pod/security/hardening-guide/overview), [Platform audit logging](/docs/platform/next/administer/configure/platform-configs/audit) | Apply a CIS benchmark baseline to the control plane cluster and decide audit log retention and SIEM integration before onboarding tenants. |

## Day 1: Stand up the first production customer cluster

:::note
Steps 3 and 4 configure Platform for your platform engineering team, not for your customers. Customers provision clusters through your product. Platform access should be restricted to your ops team.
:::

1. Install [vCluster Platform](/docs/platform/install/quick-start-guide). If building from bare metal, deploy [vCluster Standalone](/docs/vcluster/deploy/control-plane/binary/basics) first, then move to [Standalone HA](/docs/vcluster/deploy/control-plane/binary/high-availability) before production traffic.
2. Configure [backing store](/docs/vcluster/configure/vcluster-yaml/control-plane/components/backing-store) and [Platform HA](/docs/platform/next/administer/reliability-scaling/high-availability).
3. Configure [SSO](/docs/platform/next/administer/authentication/single-sign-on) and [permissions](/docs/platform/next/tenants/users-permissions/overview) for your platform engineering team.
4. Create [projects](/docs/platform/next/tenants/projects/create), [templates](/docs/platform/next/tenants/templates/overview), [quotas](/docs/platform/next/tenants/projects/quotas), and [Auto Nodes](/docs/platform/next/vmetal/concepts/machine-types-and-nodetypes) to back your customer provisioning workflows.
5. Set up [vMetal](https://www.vmetal.ai/docs/) and the [Metal3 node provider](/docs/platform/next/vmetal/drivers/bare-metal/metal3/overview): register BMC credentials, configure PXE networking, define OS images, and verify bare metal hosts reach `available`.
6. Configure per-customer network isolation with [VPN](/docs/vcluster/deploy/worker-nodes/private-nodes/vpn) and, if using Netris, the [Netris integration](/docs/vcluster/deploy/control-plane/kubernetes-pod/environment/bare-metal). Apply a default-deny [network policy](/docs/vcluster/configure/vcluster-yaml/policies/network-policy) per customer template and confirm the control plane cluster's CNI enforces it.
7. Configure per-tier [storage classes](/docs/vcluster/configure/vcluster-yaml/sync/from-host/storage-classes) and, if the scheduler needs capacity-aware placement, sync [CSI storage capacities](/docs/vcluster/configure/vcluster-yaml/sync/from-host/csi-storage-capacities).
8. Configure GPU scheduling: sync [DeviceClasses](/docs/vcluster/configure/vcluster-yaml/sync/from-host/device-classes) for device-plugin allocation, or enable [DRA ResourceClaim sync](/docs/vcluster/configure/vcluster-yaml/sync/to-host/DRA/resourceclaims) for fine-grained allocation.
9. Apply the [CIS hardening baseline](/docs/vcluster/deploy/control-plane/kubernetes-pod/security/hardening-guide/overview) to the control plane cluster and enable [Platform audit logging](/docs/platform/next/administer/configure/platform-configs/audit).
10. Install [vNode](https://www.vnode.com/docs/) on eligible GPU nodes. Configure `sync.toHost.pods.runtimeClassName: vnode` in the cluster template.
11. If you use NVIDIA Run:ai, choose a supported deployment model and install the [Run:ai Certified Stacks](/docs/platform/next/integrations/cluster-workloads/certified-stacks/runai). Otherwise, [create a StackTemplate](/docs/platform/next/tenants/templates/create-stack-templates) for the applications your AI environment requires and [add it to the cluster configuration](/docs/platform/next/tenants/consume-services/apps/use-stacks#choose-how-to-install-a-stack).
12. Validate <GlossaryTerm term="multi-tenancy">tenant isolation</GlossaryTerm> from inside the tenant cluster: confirm the customer cannot see the control plane cluster, other tenants, or platform internals.
13. Wire your product API to Platform's provisioning endpoints and test the end-to-end customer onboarding flow.
