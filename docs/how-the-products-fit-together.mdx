The <GlossaryTerm term="vcluster">vCluster</GlossaryTerm> product suite helps providers build tenant-facing products such as managed Kubernetes, Slurm environments, inference services, and Ray clusters. vCluster provides the Kubernetes <GlossaryTerm term="tenant-cluster">tenant cluster</GlossaryTerm> runtime. vCluster Platform governs tenants and capacity across a fleet. vMetal provisions and manages physical and virtual Machines. vNode adds optional workload runtime isolation.

The products are composable. You can use vCluster by itself, then add Platform for fleet governance, vMetal for Machine lifecycle management, or vNode for workload isolation. This page maps those boundaries and routes you to the canonical guide for each product.

This is a routing page, not an implementation guide. For setup and configuration, follow the links in each section.

### From product offering to infrastructure

When the products are used together, a Platform administrator publishes templates, access rules, and capacity policy. A user then creates a tenant cluster from that governed offering. vCluster runs its dedicated Kubernetes API and connects its workloads to shared or private nodes.

Administrators can join private nodes directly. With Auto Nodes, workload demand becomes a Machine request through the Platform Machine API. vMetal sends that request to the selected compute driver, which provisions a physical or virtual Machine. Network integrations can provide connectivity during that process. When configured, vNode isolates workloads at the container runtime layer.

## Products and what they own

### vCluster Platform governs tenants and capacity

Platform is the management plane for a fleet of tenant clusters. It defines projects, templates, capacity policy, access control, observability, and billing. It reconciles governance decisions across connected <GlossaryTerm term="control-plane-cluster">control plane clusters</GlossaryTerm>. Platform is where a provider decides who can create a tenant cluster and what that tenant cluster can consume.

Start with [What is vCluster Platform?](/docs/platform/)

### vCluster runs the tenant cluster

vCluster runs the tenant cluster, a full Kubernetes API that a tenant can use like any other cluster. Tenant workloads can run on shared or private nodes. Administrators can join private nodes directly. When Auto Nodes is enabled, vCluster requests Machines through the Platform Machine API as workload demand changes.

Start with [What is vCluster?](/docs/vcluster/introduction/what-are-virtual-clusters/)

### vMetal provisions and manages Machines

vMetal owns the Machine model. Each Machine is a claim on one server, physical or virtual, that moves through a driver-neutral lifecycle from request to deletion. It's a product boundary, not a single implementation or repository. Compute drivers provision Machines, including bare-metal drivers such as Metal3 and virtual-machine drivers such as KubeVirt. Network automation integrations support connectivity during provisioning. Naming a driver here describes its role in the architecture, not its shipping or support status. Check the vMetal docs for what's available today.

Auto Nodes is one way vCluster requests Machines from vMetal, not the definition of Machine provisioning.

Start with the [vMetal overview](https://www.vmetal.ai/docs/) and the [Machine and server concepts](https://www.vmetal.ai/docs/plan/concepts/machine).

### vNode adds optional workload isolation

vNode adds workload runtime isolation using Linux user namespaces, filesystem virtualization, and targeted seccomp filtering. It adds no virtual machine or virtual kubelet to the path. vNode works with shared and private nodes. It's most often paired with vCluster to add kernel-level isolation alongside control-plane isolation.

Start with the [vNode overview](https://www.vnode.com/docs/).
